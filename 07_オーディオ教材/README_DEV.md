# オーディオ教材 台本ルール

VOICEVOX（ずんだもん・四国めたん）の掛け合いで、通勤中などに聞き流せる解説音声を作ります。
台本は `scripts/epNN_slug.json`、生成した音声は `audio/epNN_slug.mp3`、文字起こしは `transcripts/epNN_slug.md` に置きます（音声と文字起こしは生成スクリプトで自動作成）。

## キャラクター

| id | キャラクター | 役割 | 口調 |
|---|---|---|---|
| `metan` | 四国めたん | 先生役。正確に分かりやすく説明する | 「〜わね」「〜よ」「〜かしら」。丁寧だが少しお嬢様口調 |
| `zundamon` | ずんだもん | 生徒役。素朴な疑問・よくある勘違いを口にする | 一人称「ボク」、語尾「〜のだ」「〜なのだ」 |

## 台本 JSON の形式

```json
{
  "id": "ep01",
  "title": "第1回 試験の全体像とCBT",
  "summary": "この回で学べること（1〜2文）",
  "related": ["../00_はじめに/01_試験概要.md"],
  "lines": [
    { "speaker": "metan", "text": "こんにちは、四国めたんよ。" },
    { "speaker": "zundamon", "text": "IPアドレス 192.168.1.0/24 なのだ。", "yomi": "アイピーアドレス、ひゃくきゅうじゅうに、てん、ひゃくろくじゅうはち、てん、いち、てん、ゼロ、スラッシュにじゅうよん、なのだ。" },
    { "pause": 3.0 }
  ]
}
```

- `text`：画面・文字起こしに表示する文。
- `yomi`（任意）：読み上げ用の文。**VOICEVOX が誤読する箇所があるときだけ** 書く。ひらがな・カタカナと読点で書く。
- `{ "pause": 秒 }`：無音を入れる（クイズで考える時間など）。
- 1行（1発話）は **80文字以内** が目安。長い説明は複数行に分ける。

## 読みの確認方法

ローカルで VOICEVOX エンジンが `http://127.0.0.1:50021` で動いています。読みは次のコマンドで確認できます（`kana` が実際の読み）。

```bash
curl -s -X POST -G http://127.0.0.1:50021/audio_query --data-urlencode "text=EVMのSPI" --data-urlencode "speaker=3" | python3 -c "import json,sys;print(json.load(sys.stdin)['kana'])"
```

確認済みの傾向：

- `TCP` `UDP` `MTBF` `SQL` `RAID` などはおおむね正しく読める。
- **IPアドレス・CIDR表記（`/24`）、分数や記号（`/` `×` `÷` `≧`）、一部の略語（`SPI` → 「エスピ・アイ」と誤読）** は誤読するので `yomi` を書く。
- 数式は読み上げに向かないので、`text` は式、`yomi` は「エムティービーエフ わる、エムティービーエフ たす エムティーティーアール」のように言葉にする。

## 構成（1回あたり 5〜7分、1,500〜2,200文字程度）

1. オープニング（2〜3行。回のテーマ紹介）
2. 本編（ずんだもんの疑問 → めたんの説明 → 具体例 → ずんだもんの言い換えで理解確認）
3. 覚え方・ひっかけ注意（試験での問われ方）
4. **ミニクイズ** 2〜3問（問題 → `pause` 3〜4秒 → 答えと理由）
5. まとめ（要点を3つ）とエンディング

## 内容のルール

- 内容は既存の Markdown 資料（`01_テクノロジ系/` など）と矛盾しないこと。
- 聞くだけで分かるように、表や図に頼らない言い方をする（「表の左の列」などは使わない）。
- 計算は「公式 → 数値 → 答え」を口頭でたどれる簡単な数値にする。
