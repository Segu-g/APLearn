# 第12回 開発プロセスとテスト技法

> ウォーターフォール・V字・プロトタイピング・アジャイルの特徴と、テスト工程、スタブとドライバ、ホワイトボックス・ブラックボックスの技法を学びます。

- 音声: [../audio/ep12_dev-test.mp3](../audio/ep12_dev-test.mp3)（約4分32秒）
- 音声合成: VOICEVOX:四国めたん、VOICEVOX:ずんだもん

**四国めたん**：こんにちは、四国めたんよ。第12回は「開発プロセスとテスト技法」を学ぶわね。

**ずんだもん**：ずんだもんなのだ。テストって、動かしてみるだけじゃないのだ？

**四国めたん**：実はテストにも、きちんとした技法があるの。まずは開発の進め方から見ていきましょう。

**ずんだもん**：開発の進め方って、いろいろあるのだ？

**四国めたん**：代表はウォーターフォールモデルよ。要件定義、設計、プログラミング、テストと順番に進め、原則として前の工程に戻らないの。

**四国めたん**：要件がはっきりしていて、変更が少ない開発に向いているわ。

**四国めたん**：それを発展させたのがV字モデル。設計の工程と、それを確かめるテストの工程を対応させるの。

**四国めたん**：内部設計は単体テスト、外部設計は結合テスト、要件定義はシステムテストや運用テストで検証するわ。

**四国めたん**：要件があいまいなら、早めに試作品を見せて確認するプロトタイピングモデルが向いているわね。

**ずんだもん**：アジャイルも聞いたことがあるのだ。

**四国めたん**：アジャイル開発は、短い期間の反復で、動くソフトウェアを少しずつ届ける進め方よ。変化への対応を重視するの。

**四国めたん**：ひっかけ注意。アジャイルは「ドキュメントが不要」という意味ではないわ。動くソフトウェアを、より重視するということよ。

**ずんだもん**：テストの工程も、順番があるのだ？

**四国めたん**：ええ。部品ごとの単体テスト、部品をつなぐ結合テスト、全体を確かめるシステムテストの順よ。

**四国めたん**：最後に、利用者が実際の業務で確かめる運用テストや、発注者の受入れテストがあるわ。

**ずんだもん**：結合テストで、まだできていない部品があったらどうするのだ？

**四国めたん**：上から順につなぐトップダウンテストでは、未完成の下位モジュールの代わりにスタブを使うの。

**四国めたん**：下から順につなぐボトムアップテストでは、上位の代わりに呼び出す役のドライバを使うわ。

**ずんだもん**：スタブは下の代役、ドライバは上の代役なのだ。運転手が車を動かすイメージなのだ！

**四国めたん**：その覚え方でいいわ。それから、修正した後に、変更していない部分へ悪影響がないかを確かめるのが回帰テストよ。

**ずんだもん**：ホワイトボックスとブラックボックスって、何の箱なのだ？

**四国めたん**：ホワイトボックステストは、プログラムの内部構造、つまり分岐や命令に注目してテストケースを作る技法よ。

**四国めたん**：すべての命令を1回は通す命令網羅、すべての判定の真と偽を1回ずつ通す判定網羅などがあるわ。

**四国めたん**：判定の中の、個々の条件の真と偽を通すのが条件網羅。

**四国めたん**：ひっかけ注意。条件網羅を満たしても、判定網羅を満たすとは限らないの。

**四国めたん**：ブラックボックステストは、中身を見ずに、仕様の入力と出力に注目する技法よ。

**四国めたん**：例えば、0歳から17歳は子ども料金、18歳から64歳は大人料金、65歳以上はシニア料金という仕様を考えましょう。

**四国めたん**：同値分割では、グループごとに代表値を一つずつ選ぶの。マイナスの年齢のような、誤った入力のグループも忘れずにね。

**四国めたん**：境界値分析では、境目の前後を選ぶわ。17歳と18歳、64歳と65歳、そして0歳とマイナス1歳よ。

**ずんだもん**：なんで境目ばかり狙うのだ？

**四国めたん**：「より小さい」と「以下」の書き間違いは、境目でしか見つからないからよ。

**四国めたん**：では、ミニクイズよ。第1問。トップダウンテストで、未完成の下位モジュールの代わりに使うものは何？

*（3.5秒 考えてみよう）*

**ずんだもん**：下の代役だから、スタブなのだ！

**四国めたん**：正解よ。

**四国めたん**：第2問。「20歳以上は成人」という仕様。境界値分析で選ぶ二つの年齢は何歳と何歳かしら。

*（3.5秒 考えてみよう）*

**四国めたん**：答えは、19歳と20歳よ。境目のすぐ手前と、ちょうど境目の年齢ね。

**四国めたん**：第3問。プログラムを修正した後、変更していない部分に悪影響がないかを確かめるテストは？

*（3.5秒 考えてみよう）*

**四国めたん**：答えは回帰テスト、リグレッションテストよ。何度も繰り返すから、自動化と相性がいいの。

**四国めたん**：今日のまとめよ。一つ目。V字モデルでは、上流の設計ほど、後のテストで検証される。

**四国めたん**：二つ目。スタブは呼ばれる下位の代役、ドライバは呼び出す上位の代役。

**四国めたん**：三つ目。ホワイトボックスは内部構造、ブラックボックスは仕様に注目。境界値は境目の前後を選ぶ。

**ずんだもん**：テストにも作戦があるのだ！

**四国めたん**：次回は、プロジェクトマネジメントのクリティカルパスとEVMよ。またね。
