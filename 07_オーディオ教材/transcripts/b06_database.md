# 科目B攻略6 データベース

> 科目B問6データベースの特徴と出題傾向、E-R図の多重度を本文から決める手順、内部結合と外部結合の使い分けを、令和5年度春期の問6で学びます。

**冥鳴ひまり**：こんにちは、冥鳴ひまりです。科目B攻略編、第6回はデータベースです。

**春日部つむぎ**：春日部つむぎだよ！データベースって、SQLがいっぱい出てくるやつでしょ？あーし、ちょっと身構えちゃう。

**冥鳴ひまり**：大丈夫ですよ、つむぎ先輩。この分野は問われ方の型が決まっていて、対策が点になりやすいんです。

**春日部つむぎ**：じゃあ、どんな人が選ぶと得なの？

**冥鳴ひまり**：SQLやE-R図を一度でも学んだ人、アプリ開発の経験がある人には、とてもおすすめです。

**冥鳴ひまり**：逆に、SQLをまったく触ったことがない人は、本番でいきなり選ぶのは避けましょう。構文を知らないと手が出ない空欄があるんです。

**春日部つむぎ**：知識で勝負する分野ってことね。

**春日部つむぎ**：で、実際どんなのが出てるの？

**冥鳴ひまり**：令和4年度から令和7年度までの8回分を見ると、毎回ほぼ同じ骨組みです。前半がE-R図の空欄、後半がSQLの空欄と、短い記述ですね。

**冥鳴ひまり**：E-R図では、エンティティどうしの関連、つまり1対1か1対多かを答える設問が、ほぼ毎回出ています。

**冥鳴ひまり**：SQLは回によって色が違います。令和5年度秋期は、直近7日間の平均を求めるウィンドウ関数でした。

**冥鳴ひまり**：令和6年度秋期は、カテゴリの階層をたどる再帰的な問合せと、インデックスを張る列の選び方。正答率が低めの難しい回でした。

**冥鳴ひまり**：表を作る、列を足す、権限を与える構文もよく出ます。

**冥鳴ひまり**：令和4年度春期と令和7年度秋期では、既存の表に手を加える命令として、ALTER TABLE が答えになりました。

**春日部つむぎ**：SQLは回ごとに違うけど、E-R図の関連はほぼ毎回。E-R図は絶対落とせないじゃん。

**春日部つむぎ**：解くときって、どこから読めばいいの？

**冥鳴ひまり**：まず設問をざっと見て、E-R図の空欄、SQLの空欄、記述の数を確かめます。そのあと本文の業務説明を、1文ずつE-R図と対応させていきます。

**冥鳴ひまり**：たとえば「1人の従業員が複数の部署を管理する場合がある」という一文。これは、従業員が1、部署が多という関係の根拠になります。

**冥鳴ひまり**：凡例では、1対多の関連は、多の側に矢印の先を向けます。図の配置まで見て、向きを決めましょう。

**春日部つむぎ**：矢印の先っぽが「たくさんある方」ね。りょ。

**冥鳴ひまり**：もう一つ大事なのが、多の側には、1の側の主キーが外部キーとして入る、というルールです。属性の空欄はこれでかなり埋まります。

**冥鳴ひまり**：SQLの空欄は、構文の知識で即答できるものから片付けます。そのあと、出力される表の行と列を思い描いてから、結合や集計に戻りましょう。

**冥鳴ひまり**：記述は最後に、本文から根拠を探して書きます。

**冥鳴ひまり**：では過去問を1題見てみましょう。出典は令和5年度春期、応用情報技術者試験、午後、問6です。

**冥鳴ひまり**：ソフトウェア開発会社が、年間の総労働時間などのKPIを、組織ごとに集計するシステムを作る話です。

**冥鳴ひまり**：毎月のバッチ処理で、まず一時表を3つ作ります。従業員と所属組織の対応、従業員ごとの目標の集計、そして実績の集計です。

**冥鳴ひまり**：最後にこの3つを結合して集計リストを作ります。設問は、その結合方法を答える空欄なんです。

**春日部つむぎ**：結合って、内部結合と外部結合があるやつだよね。どう選ぶの？

**冥鳴ひまり**：本文の考慮事項がヒントです。年度の途中で入社した人や退職した人は、評価の対象から外したいと書かれています。

**冥鳴ひまり**：所属の一時表には退職者がいません。目標の一時表には、年度初めに未入社だった人がいません。

**冥鳴ひまり**：ですから、両方の表にそろっている従業員だけを残せばいい。両方にある行だけを残すのは内部結合、INNER JOIN です。

**春日部つむぎ**：途中で入った人も、途中で辞めた人も、どっちかの表にいないから自然に消えるんだ。賢い。

**冥鳴ひまり**：次の空欄は、実績の一時表との結合です。実績が1件もない従業員には、実績の行そのものがありません。

**冥鳴ひまり**：それでも対象の従業員として、人数や目標には数えたい。だから左側の行をすべて残す、左外部結合、LEFT OUTER JOIN が答えです。

**春日部つむぎ**：あ、でも相手がいない行って、実績のところが空っぽにならない？

**冥鳴ひまり**：鋭いですね。その行は、実績の値が NULL になります。そこで COALESCE という関数で、NULL を0に置き換えているんです。

**冥鳴ひまり**：記述の設問は、その NULL がどのデータの、どんな場合に起きるかを40字以内で答えるものでした。

**冥鳴ひまり**：解答例は「該当従業員のKPI項目に対する実績データが、1件も存在しない場合」です。

**冥鳴ひまり**：根拠は「日別実績のない従業員のレコードは作成しない」という一文です。講評でも、この設問の正答率は低かったそうです。

**春日部つむぎ**：「両方にある人だけ」なら内部結合、「いなくても残す」なら左外部結合、で、残した行はNULLになるからゼロに直す。セットで覚えるわ。

**春日部つむぎ**：ほかに、引っかかりやすいとこってある？

**冥鳴ひまり**：まず下線です。主キーは実線、外部キーは破線の下線を付けます。属性名を書く設問は、この下線まで採点されるんです。

**冥鳴ひまり**：令和7年度の春期でも秋期でも、主キーの実線の下線を付け忘れた解答が目立ったそうです。

**春日部つむぎ**：名前は合ってるのに、線ひとつで落とすってこと？もったいなさすぎ。

**冥鳴ひまり**：そうなんです。下線を忘れると、点数が冥界送りになりますよ。

**春日部つむぎ**：ひまっち、さらっと怖いこと言うじゃん……。

**冥鳴ひまり**：次に、1対1と1対多の取り違えです。令和4年度秋期では、同じ回線番号のまま2年ごとに端末を交換する、という記述がありました。

**冥鳴ひまり**：1つの契約に、時期をずらして端末が複数つながるので、契約が1、端末が多です。ここを1対1と答えた誤りが見られました。

**冥鳴ひまり**：多対多の関係は、連関エンティティをはさんで、1対多の2本に分けます。令和6年度秋期の、利用者が利用者をフォローする関係がそうでした。

**冥鳴ひまり**：最後に、構文の暗記です。既存の表を変える ALTER TABLE、件数を数える COUNT、範囲指定の BETWEEN、並べ替えの ORDER BY。

**冥鳴ひまり**：それに、権限を与える GRANT、参照先が消えたら参照元も消す ON DELETE CASCADE。このあたりは、知っていれば確実に取れる空欄です。

**春日部つむぎ**：WHEREとHAVINGの違いも、念のため確認させて！

**冥鳴ひまり**：WHERE は集計する前の行を絞り込み、HAVING は集計した後のグループを絞り込みます。順番で覚えましょうね。

**冥鳴ひまり**：では、ミニクイズです。1問目。「1つの取引の商品を分けて発送することも、複数の取引をまとめて発送することもできない」。取引と発送の関係は何でしょう？

*（4秒 考えてみよう）*

**春日部つむぎ**：分けられないし、まとめられない……。1対1！

**冥鳴ひまり**：正解です。令和6年度秋期の問題で、1つの取引に発送が1つだけ対応するので、1対1の関連になります。

**冥鳴ひまり**：2問目。参照先の表の行が削除されたら、参照元の表の行も自動的に削除されるようにしたい。外部キーにどんな指定を付けますか？

*（4秒 考えてみよう）*

**春日部つむぎ**：えっと、ON DELETE CASCADE！

**冥鳴ひまり**：正解です。令和7年度秋期で出題されました。講評によると、ここに属性名を書いてしまった誤答があったそうです。

**冥鳴ひまり**：それでは、まとめです。1つ目。E-R図の関連は、本文の業務説明から1か多かを決め、矢印の先は多の側に向けます。

**冥鳴ひまり**：2つ目。両方にある行だけなら内部結合、相手がなくても残すなら左外部結合。残った行の NULL は COALESCE で0にします。

**冥鳴ひまり**：3つ目。主キーの実線、外部キーの破線の下線と、ALTER TABLE などの基本構文は、確実に点にしましょう。

**春日部つむぎ**：関連は本文から、結合は残したい行から、下線と構文は絶対落とさない。データベース、思ったよりいけそうじゃん！

**冥鳴ひまり**：次回の第7回は、組込みシステム開発です。また一緒に学びましょうね。

**春日部つむぎ**：またね〜！
