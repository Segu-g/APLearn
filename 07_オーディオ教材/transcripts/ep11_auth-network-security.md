# 第11回 認証とネットワークセキュリティ

> 多要素認証、TLS、ファイアウォール・WAF・IDS・IPS、送信ドメイン認証（SPF・DKIM・DMARC）、ゼロトラストの役割の違いを整理します。

- 音声: [../audio/ep11_auth-network-security.mp3](../audio/ep11_auth-network-security.mp3)（約5分22秒）
- 音声合成: VOICEVOX:四国めたん、VOICEVOX:ずんだもん

**四国めたん**：こんにちは、四国めたんよ。第11回は「認証とネットワークセキュリティ」。守りの技術を一気に見ていくわね。

**ずんだもん**：ずんだもんなのだ。機械の名前がアルファベットばかりで、目が回りそうなのだ。

**四国めたん**：それぞれ「何を見て、何をするか」で区別すれば大丈夫よ。

**ずんだもん**：多要素認証って、パスワードを2回入れることなのだ？

**四国めたん**：違うわ。認証の要素は、知識情報、所持情報、生体情報の三つよ。

**四国めたん**：パスワードは知識、スマートフォンやICカードは所持、指紋や顔は生体ね。

**四国めたん**：異なる要素を二つ以上組み合わせるのが、多要素認証よ。

**四国めたん**：「パスワードと秘密の質問」は、どちらも知識情報。二段階ではあっても、多要素認証ではないわ。

**ずんだもん**：回数じゃなくて、種類が違うことが大事なのだ。

**四国めたん**：そうよ。さらにFIDOやパスキーは、端末の中の秘密鍵で署名する方式で、フィッシングに強いの。

**ずんだもん**：TLSは、何をしてくれるのだ？

**四国めたん**：TCPの上で、通信の暗号化、改ざんの検出、サーバの認証をするプロトコルよ。HTTPSで使われているわね。

**四国めたん**：今の主流はTLS1.2と1.3。SSLや古いTLSは脆弱なので使わないわ。

**四国めたん**：TLS1.3では、毎回使い捨ての共通鍵を共有するの。

**四国めたん**：だから、サーバの秘密鍵が後で漏れても、過去の通信は解読されない。この性質を前方秘匿性というわ。

**四国めたん**：ひっかけ注意。TLSが守るのは通信経路よ。サーバに保存されたデータや、端末に入り込んだマルウェアからは守れないわ。

**ずんだもん**：ファイアウォールとWAFとIDSの違いが、分からないのだ。

**四国めたん**：ファイアウォールは、IPアドレスやポート番号などを見て、通信を許可したり遮断したりする仕組みよ。

**四国めたん**：ルールは上から順に評価するわ。最後に「すべて拒否」を置いて、必要な通信だけを許可するのが基本ね。

**四国めたん**：WAFは、Webアプリへの通信の中身を検査して、SQLインジェクションやXSSを遮断するの。

**四国めたん**：IDSは、不正な通信を検知して、管理者に知らせるだけ。検知して遮断までするのがIPSよ。

**ずんだもん**：IDSは見張り番、IPSは門番なのだ。

**四国めたん**：いい例えね。それから、公開するサーバはDMZに置き、顧客情報を持つデータベースは内部側に置くのよ。

**ずんだもん**：なりすましメールは、どうやって防ぐのだ？

**四国めたん**：送信ドメイン認証を使うわ。SPFは、送信側ドメインのDNSに、正規の送信サーバのIPアドレスを登録しておく方式よ。

**四国めたん**：DKIMは、送信側のメールサーバが秘密鍵で署名を付け、受信側がDNSの公開鍵で検証する方式。途中の改ざんも分かるわ。

**四国めたん**：DMARCは、SPFとDKIMの結果に加えて、利用者に見えるFromのドメインが一致するかを確かめるの。

**四国めたん**：失敗したときの扱いは送信側がDNSで宣言するわ。何もしないnone、隔離するquarantine、拒否するrejectの三つよ。

**ずんだもん**：SPFはIPアドレス、DKIMは署名、DMARCはその結果をまとめて方針を決める、なのだ。

**四国めたん**：そうよ。どれも本文の暗号化はしない点に注意してね。

**ずんだもん**：最後は、ゼロトラストなのだ。

**四国めたん**：社内ネットワークだから安全とは考えず、すべてのアクセスを信頼せずに、毎回検証する考え方よ。

**四国めたん**：クラウドやテレワークが広がって、内と外の境界があいまいになったことが背景ね。

**四国めたん**：利用者の認証、端末の状態、場所や時刻などをもとに、アクセスのたびに許可するかを判断するの。

**ずんだもん**：社内にいても、毎回チェックされるのだ。

**四国めたん**：では、ミニクイズよ。第1問。パスワードと、スマートフォンに届く確認コード。これは多要素認証かしら？

*（3.5秒 考えてみよう）*

**四国めたん**：答えは、多要素認証よ。パスワードは知識情報、スマートフォンは所持情報で、種類が違うからね。

**四国めたん**：第2問。不正な通信を検知して管理者に通知するけれど、遮断はしない仕組みは何？

*（3.5秒 考えてみよう）*

**ずんだもん**：見張り番のIDSなのだ！

**四国めたん**：正解よ。

**四国めたん**：第3問。送信側ドメインのDNSに、正規の送信サーバのIPアドレスを登録しておく技術は何かしら。

*（3.5秒 考えてみよう）*

**四国めたん**：答えはSPFよ。署名を使うのはDKIMだったわね。

**四国めたん**：今日のまとめよ。一つ目。多要素認証は、知識・所持・生体のうち、異なる要素を組み合わせる。

**四国めたん**：二つ目。ファイアウォールはアドレスとポート、WAFはWebの中身。IDSは検知だけ、IPSは遮断まで。

**四国めたん**：三つ目。メールはSPF・DKIM・DMARCで送信元を確かめ、ゼロトラストではすべてのアクセスを毎回検証する。

**ずんだもん**：守りの道具の使い分け、すっきりしたのだ！

**四国めたん**：次回は、開発プロセスとテスト技法よ。またね。
