## 練習問題1 情報セキュリティ：ECサイトへの不正ログイン

**目安時間：20分**　（オリジナル問題）

### 本文

K社は、日用品を販売するECサイトを運営している。会員は、メールアドレスを利用者IDとし、パスワードを使ってログインする。ECサイトのログイン機能には、**同一の利用者IDで連続5回ログインに失敗すると、その利用者IDを30分間ロックする** 機能がある。

ある日、複数の会員から「身に覚えのない注文がある」という問合せがあった。情報システム部のL主任がWebサーバのログを調査したところ、次のことが分かった。

- 〔ログの特徴1〕 深夜2時から4時の間に、**約3万件の異なる利用者ID** に対してログイン試行が行われていた。
- 〔ログの特徴2〕 **1つの利用者IDに対する試行は1回だけ** で、そのうち約300件がログインに成功していた。
- 〔ログの特徴3〕 ログインに成功した利用者IDの多くは、**他社のWebサービスと同じパスワード** を使っていた会員のものであった。
- 〔ログの特徴4〕 試行の送信元IPアドレスは、海外の多数のIPアドレスに分散していた。

L主任は、この攻撃が、他のサービスから漏えいした利用者IDとパスワードの組みを使って不正にログインを試みる **【 a 】** であると判断した。

また、L主任は、商品やキャンペーンを管理するECサイトの **管理画面** も、インターネット上のどこからでも利用者IDとパスワードだけでアクセスできる状態であることに気づき、追加の対策が必要だと考えた。

### 設問

**設問1** 本文中の **【 a 】** に入れる最も適切な字句を解答群の中から選び、記号で答えよ。

> 解答群　ア：辞書攻撃　イ：パスワードリスト攻撃　ウ：ブルートフォース攻撃　エ：リバースブルートフォース攻撃

**設問2** 今回の攻撃では、ログイン機能のアカウントロック機能が働かなかった。その理由を、〔ログの特徴〕に着目して **35字以内** で述べよ。

**設問3** 会員の不正ログインの被害を防ぐために、会員のログイン方式について K社が導入すべき技術的対策を **20字以内** で述べよ。

**設問4** 管理画面について、L主任が考えた追加の対策を **2つ**、それぞれ **25字以内** で述べよ。

<details><summary>模範解答・採点ポイント</summary>

#### 模範解答

| 設問 | 模範解答 | 字数（英数字も1字として計数） |
|---|---|---|
| 設問1 | **イ**（パスワードリスト攻撃） | ― |
| 設問2 | 1つの利用者IDに対する試行が1回だけで、連続5回の失敗に達しないため | 35字 |
| 設問3 | ログイン時に多要素認証を導入する | 16字 |
| 設問4 | ① 管理画面への接続元IPアドレスを社内に限定する<br>② 管理者のログインに多要素認証を導入する | ① 23字<br>② 19字 |

#### 採点ポイント

- **設問1**：他のサービスから漏えいしたIDとパスワードの **組み** を使い回す攻撃＝パスワードリスト攻撃（クレデンシャルスタッフィングとも呼ばれます）。
  - ア 辞書攻撃：辞書の単語をパスワードとして試す。
  - ウ ブルートフォース攻撃：1つのIDに対して全パターンのパスワードを試す。
  - エ リバースブルートフォース攻撃：パスワードを固定し、IDを次々に変えて試す。
  - ⚠️ 「IDごとに1回だけ」という特徴はエにも当てはまりますが、〔ログの特徴3〕（他社と同じパスワード）が決め手でイになります。
- **設問2**：「**IDごとの試行が1回**」と「**ロックの条件（同一IDで連続5回）に達しない**」の **2要素** が必要。片方だけなら部分点の扱いになると考えられます。
  - ✕「攻撃元のIPアドレスが分散していたため」→ アカウントロックはIP単位ではなく **ID単位** の機能なので、理由として不十分。
- **設問3**：「多要素認証」「二要素認証」「ワンタイムパスワードの併用」などが正解の範囲。
  - ✕「パスワードを複雑にさせる」→ 漏えいしたパスワードがそのまま使われる攻撃なので、効果がない。
  - △「会員にパスワードの使い回しをやめるよう注意喚起する」→ 技術的対策ではない。
- **設問4**：本文の問題点「**インターネット上のどこからでも**」→ アクセス元制限、「**IDとパスワードだけ**」→ 認証強化、と本文の記述に1対1で対応させるのがコツ。「VPN経由でのみ接続可能にする」も可。

</details>

## 練習問題2 データベース：文具通販の売上集計

**目安時間：25分**　（オリジナル問題）

### 本文

M社は、文具を販売する会員制の通信販売を行っている。販売管理システムのデータベースの関係スキーマ（表の構造）を次に示す。下線（ここでは `[PK]`）は主キー、`[FK]` は外部キーを表す。

```
会員（会員番号[PK], 会員名, 登録日）
商品（商品番号[PK], 商品名, 単価）
注文（注文番号[PK], 会員番号[FK], 注文日）
注文明細（注文番号[PK][FK], 明細番号[PK], 商品番号[FK], 数量）
```

- 1回の注文で複数の商品を購入でき、商品ごとに注文明細が1行作成される。
- 会員は、注文を一度もしていなくても会員表に登録されている。

各表のデータの一部（抜粋）を示す。

| 会員番号 | 会員名 | 登録日 |
|---|---|---|
| M1 | 佐藤 | 2025-01-10 |
| M2 | 鈴木 | 2025-03-01 |
| M3 | 高橋 | 2026-08-20 |

| 商品番号 | 商品名 | 単価 |
|---|---|---|
| P1 | ノート | 300 |
| P2 | ペン | 150 |
| P3 | ファイル | 500 |

| 注文番号 | 会員番号 | 注文日 |
|---|---|---|
| O1 | M1 | 2026-09-03 |
| O2 | M2 | 2026-09-15 |
| O3 | M1 | 2026-09-28 |
| O4 | M2 | 2026-10-02 |

| 注文番号 | 明細番号 | 商品番号 | 数量 |
|---|---|---|---|
| O1 | 1 | P1 | 2 |
| O1 | 2 | P2 | 4 |
| O2 | 1 | P3 | 3 |
| O3 | 1 | P1 | 5 |
| O4 | 1 | P2 | 10 |

〔SQL1〕 2026年9月の商品別売上金額のうち、**1,000円以上の商品だけ** を、売上金額の多い順に表示する。

```sql
SELECT 商品.商品番号, 商品.商品名, SUM(注文明細.数量 * 商品.単価) AS 売上金額
  FROM 注文
  JOIN 注文明細 ON 注文.注文番号 = 注文明細.注文番号
  JOIN 商品 ON 注文明細.商品番号 = 商品.商品番号
 WHERE 注文.注文日 BETWEEN '2026-09-01' AND '2026-09-30'
 GROUP BY 商品.商品番号, 商品.商品名
【 b 】 SUM(注文明細.数量 * 商品.単価) >= 1000
 ORDER BY 売上金額 【 c 】
```

〔SQL2〕 2026年9月に **一度も注文しなかった会員も含めて**、全会員の9月の注文回数を表示する。

```sql
SELECT 会員.会員番号, 会員.会員名, COUNT(【 e 】) AS 注文回数
  FROM 会員 【 d 】 注文
    ON 会員.会員番号 = 注文.会員番号
   AND 注文.注文日 BETWEEN '2026-09-01' AND '2026-09-30'
 GROUP BY 会員.会員番号, 会員.会員名
```

### 設問

**設問1** 会員と注文の関係、注文と注文明細の関係のカーディナリティ（多重度）を、それぞれ「1対1」「1対多」「多対多」のいずれかで答えよ。

**設問2** 〔SQL1〕の **【 b 】【 c 】** に入れる適切な字句を答えよ。

**設問3** 〔SQL1〕を上記のデータに対して実行した結果を、すべての行について答えよ。

**設問4** 〔SQL2〕の **【 d 】** に入れる適切な字句を答えよ。また、【 d 】に `JOIN`（内部結合）を使うと、どのような不具合が起きるかを **30字以内** で述べよ。

**設問5** 〔SQL2〕の **【 e 】** に `*` を入れると、会員M3（高橋）の注文回数が正しく表示されない。【 e 】に入れるべき適切な字句を答え、`*` では正しくない理由を **35字以内** で述べよ。

<details><summary>模範解答・採点ポイント</summary>

#### 模範解答

| 設問 | 模範解答 |
|---|---|
| 設問1 | 会員と注文：**1対多** ／ 注文と注文明細：**1対多** |
| 設問2 | b：**HAVING**　c：**DESC** |
| 設問3 | (P1, ノート, 2100)、(P3, ファイル, 1500) の2行（この順） |
| 設問4 | d：**LEFT OUTER JOIN**（または LEFT JOIN）<br>不具合：9月に注文がない会員が結果に表示されない（20字） |
| 設問5 | e：**注文.注文番号**<br>理由：COUNT(*)は結合で生じたNULLの行も数え、0件が1件になるため（35字） |

#### 採点ポイント・解説

- **設問1**：1人の会員は複数回注文できるが、1つの注文は1人の会員のもの → **1対多**。注文明細は注文番号を主キーの一部に持つ「多」側。
  - 💡「**外部キーを持つ側が『多』**」と覚えると速く判断できます。
- **設問2**：集計結果（SUM）で絞り込むので **HAVING**。WHERE は集計前の行に対する条件なので、SUM を書けません。「多い順」は降順＝ **DESC**。
- **設問3**（Pythonの sqlite3 で実行して検算済み）：
  - P1：O1 の 2個 + O3 の 5個 = 7個 × 300円 = **2,100円**
  - P3：O2 の 3個 × 500円 = **1,500円**
  - P2：9月は O1 の 4個 × 150円 = 600円 → 1,000円未満なので **表示されない**（O4 は10月なので対象外）
  - ⚠️ O4（10月）の P2 10個を含めてしまうと誤り。WHERE の期間条件の確認がポイント。
- **設問4**：内部結合では、結合相手（9月の注文）がない会員 M3 の行が消えます。「全会員を表示する」という要件 → 左側の表（会員）の行をすべて残す **左外部結合** が必要です。
- **設問5**：外部結合で相手がない行は、注文側の列がすべて **NULL** の1行になります。`COUNT(*)` は行数を数えるので M3 が **1** になり、`COUNT(注文.注文番号)` は NULL を数えないので **0** になります（sqlite3 で検算済み：`COUNT(*)` では M3 = 1）。
  - 採点の要素：「NULLの行も数える」＋「0件が1件になる（正しく0にならない）」。

</details>

## 練習問題3 プロジェクトマネジメント：進捗遅延への対応

**目安時間：25分**　（オリジナル問題）

### 本文

N社は、自社の販売管理システムを再構築するプロジェクトを立ち上げた。プロジェクトマネージャ（PM）は情報システム部のP課長である。開発の一部はソフトウェア会社Q社に委託しており、Q社とは **請負契約** を結んでいる。

プロジェクトの完成時総予算（BAC）は **2,400万円**、期間は **12週間** である。P課長は、EVM（Earned Value Management：アーンドバリューマネジメント）で進捗とコストを管理している。

〔第6週末の状況〕

| 指標 | 値 |
|---|---|
| PV（計画価値） | 1,200万円 |
| EV（出来高） | 1,000万円 |
| AC（実コスト） | 1,100万円 |

遅れの主な原因は、N社の営業部から **要件の追加が口頭で何度も持ち込まれ**、開発チームがその都度対応していたことであった。追加要件は、**変更管理の手続を経ずに** 作業に組み込まれていた。

また、Q社の担当範囲にも遅れが出ていたため、N社の開発リーダのR氏は、**Q社の開発要員に直接、作業の優先順位や作業時間の指示を出そう** と考え、P課長に相談した。

### 設問

**設問1** 第6週末の SV（スケジュール差異）、CV（コスト差異）、SPI（スケジュール効率指数）、CPI（コスト効率指数）を求めよ。SPI と CPI は小数第3位を四捨五入して小数第2位まで答えよ。

**設問2** 今後も第6週末までと同じコスト効率で作業が進むと仮定した場合の、EAC（完成時総コスト見積り）を求めよ（万円単位）。

**設問3** 遅れの原因を踏まえ、P課長が今後の要件追加に対して取るべき対応を **40字以内** で述べよ。

**設問4** R氏の考えに対して、P課長は「その方法は契約上問題がある」と指摘した。どのような問題があるかを **35字以内** で述べよ。また、Q社の遅れに対して N社が取るべき適切な対応を **30字以内** で述べよ。

<details><summary>模範解答・採点ポイント</summary>

#### 模範解答

| 設問 | 模範解答 |
|---|---|
| 設問1 | SV = **−200万円**、CV = **−100万円**、SPI = **0.83**、CPI = **0.91** |
| 設問2 | EAC = **2,640万円** |
| 設問3 | 要件追加は変更管理の手続で影響を評価し、関係者の承認を得てから作業に組み込む（38字） |
| 設問4 | 問題：請負契約の要員に発注者が直接指揮命令すると偽装請負になる（28字）<br>対応：Q社の責任者に遅れの原因と挽回策の報告を求める（23字） |

#### 採点ポイント・解説

- **設問1**（Pythonで検算済み）
  - `SV = EV − PV = 1,000 − 1,200 = −200`（マイナス → 遅れ）
  - `CV = EV − AC = 1,000 − 1,100 = −100`（マイナス → コスト超過）
  - `SPI = EV / PV = 1,000 / 1,200 = 0.8333… → 0.83`
  - `CPI = EV / AC = 1,000 / 1,100 = 0.9090… → 0.91`
  - ⚠️ 差は「EV − 〇〇」、比は「EV ÷ 〇〇」。PV と AC を逆にするミスが多い。
- **設問2**：`EAC = BAC / CPI = 2,400 / (1,000 / 1,100) = 2,400 × 1.1 = 2,640万円`
  - ⚠️ CPI を四捨五入した 0.91 で割ると 2,637.4… となりずれます。**丸める前の値（分数）で計算** するのが安全です。
  - 参考：残作業を **当初の計画どおりのコスト効率** で進めると仮定する場合は `EAC = AC + (BAC − EV) = 1,100 + 1,400 = 2,500万円` です。設問の仮定を読み分けましょう。
- **設問3**：本文の問題点「口頭で持ち込まれ」「変更管理の手続を経ずに」に対応させ、
  - 要素①：**変更管理の手続**（変更要求を文書で受け付ける）
  - 要素②：**影響（スケジュール・コスト）の評価**
  - 要素③：**承認**（ステークホルダ・変更管理委員会）
  の3つのうち2つ以上が入っていれば得点できると考えられます。「営業部の要件追加を断る」だけでは不十分です。
- **設問4**：
  - **請負契約** では、受託者（Q社）が自らの責任で仕事を完成させ、**要員への指揮命令は受託者が行う**。発注者（N社）が直接指示すると、実態が労働者派遣とみなされる **偽装請負** になるおそれがあります。
  - 対応は「**Q社（の責任者）を通じて**」が必須の要素。進捗報告・挽回計画の提出を求める、契約に基づき協議する、などが正解の範囲です。
  - 💡 **準委任契約** も、要員への指揮命令は受託者が行う点は同じです（直接指揮命令できるのは **労働者派遣契約**）。

</details>
