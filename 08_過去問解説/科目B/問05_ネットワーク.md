## 令和7年度秋期 問5「クラウドサービスへの移行」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_ap_pm_qs.pdf)（30〜34 ページ）
- 難易度：★★
- 出題趣旨：社内サーバを仮想サーバによるクラウド環境へ移行する事例を題材に、DHCP、DNS、NAT、経路制御などIPネットワークの基本機能の理解を問う。

### 状況設定

オフィス機器販売のA社は、本社のDMZと内部LANにあるサーバを、B社クラウド上の専用環境BCL-Aへ移す。対象はWeb、メール中継、プロキシ、外部DNS、キャッシュDNS、メール、内部DNSの各サーバで、業務サーバは本社に残す。移行後は、公開セグメントのサーバがNAT機能をもつIGW経由でインターネットと通信し、本社とはIPsecルータ同士で接続する。社内PCの操作や運用方法は変えないことを前提に、FWルール、NAT、経路表、DHCPの配付情報の変更を設計する。

### 設問と解き方

#### 設問1(1)

- **問われていること**：下線①について、営業所のPCに設定するデフォルトゲートウェイのIPアドレスをもつ機器（図1中の名称）。
- **解答例**：L3SW0

**解き方**：図1で営業所のPCは 192.168.1.0/24 のセグメントにあり、L2SW0 を通って L3SW0 につながっている。デフォルトゲートウェイは自セグメントの外へ出るときの最初のルータなので、このセグメントに直接接続しているレイヤー3機器 L3SW0 が該当する。L2SW0 はレイヤー2機器なのでIPルーティングは行わない。

#### 設問1(2)

- **問われていること**：下線②のオープンリレー防止策で、メール中継サーバが防止すべき処理（40字以内）。
- **解答例**：社外のメールサーバから送信された社外宛てのメールを中継する処理

**解き方**：メール中継サーバの本来の役割は2つ（現在のネットワーク構成の説明）。メールサーバから社外宛てへの中継と、社外から A社宛てのメールサーバへの中継である。これ以外の「社外から社外へ」の中継を許すと、第三者がスパム送信の踏み台にできてしまう（オープンリレー）。したがって送信元も宛先も社外のメールの中継を防ぐ。講評によれば、OP25B は ISP 利用者の直接送信を防ぐ別の技術なので混同しないこと。

#### 設問1(3) a

- **問われていること**：表1：インターネット→DMZで TCP/443 を許可する宛先。
- **解答例**：Webサーバ

**解き方**：TCP/443 は HTTPS。本文に「DMZ の Web サーバは HTTP Over TLS によるアクセスだけを受け付ける」とあるので、インターネットから443番で受け付ける DMZ のサーバは Web サーバ。

#### 設問1(3) b

- **問われていること**：表1：インターネット→DMZで TCP/53・UDP/53（DNS）を許可する宛先。
- **解答例**：外部DNSサーバ

**解き方**：インターネットからの名前解決の問合せを受け付けるのは、A社.jp のゾーン情報を管理する権威サーバである外部DNSサーバ。キャッシュDNSサーバは社内からの問合せを外へ転送する役割なので、表1では DMZ→インターネットの送信元に入っている。

#### 設問1(3) c

- **問われていること**：表1：DMZ→インターネットで TCP/80・TCP/443 を許可する送信元。
- **解答例**：プロキシサーバ

**解き方**：本文に「社内PCは、インターネット上の Web サイト及び DMZ の Web サーバに、DMZ のプロキシサーバ経由でアクセスする」とある。インターネットの Web サイトへ HTTP/HTTPS で出ていくのはプロキシサーバ。

#### 設問2(1)

- **問われていること**：下線③で、A社宛てのSMTPパケットがIGWを通過する前と後の宛先IPアドレス。
- **解答例**：通過前：200.α.β.2　通過後：172.20.1.14

**解き方**：A社宛てのメール（SMTP）をインターネットから受け取るのはメール中継サーバ。移行後もインターネット向けには移行前と同じグローバルアドレスを使うので、図1の表から IGW 通過前の宛先は 200.α.β.2。IGW は NAT で公開セグメントのアドレスに変換する。図2の公開セグメントの表で、メール中継サーバは 172.20.1.14 なので、通過後の宛先はこのアドレスになる。本文の変換規則は「11〜14 → .1〜.3, .5」と範囲で書かれているが、アドレスの順番ではなくサーバ名で対応付けること。

#### 設問2(2)

- **問われていること**：下線④で、IPsecルータ1がBCL-Aのサーバに転送するパケットの送信元ネットワークアドレス（図2の表記で全て）。
- **解答例**：192.168.1.0/24，172.16.128.0/20

**解き方**：社内PCの運用方法と操作は変わらないので、本社と営業所のPCは引き続きプロキシサーバ・メールサーバ・内部DNSサーバを使う。これらは BCL-A に移るので、PCのセグメントである 192.168.1.0/24（営業所）と 172.16.128.0/20（本社）からのパケットが IPsec ルータ1経由でサーバに届く。業務サーバのある 172.16.0.0/24 は「業務サーバは社内PCとだけ通信する」とあるので、BCL-A へは通信しない。

#### 設問2(3)

- **問われていること**：下線⑤で、L3SW0とL3SW1の社内PCを送信元とする経路の変更が必要になるのは、どのサーバの移行によるか（図2の名称で全て）。
- **解答例**：プロキシサーバ，メールサーバ，内部DNSサーバ

**解き方**：社内PCが直接通信するサーバを洗い出す。名前解決は内部DNSサーバ、メールの送受信はメールサーバ、Web アクセスはプロキシサーバへ行う。Web サーバへはプロキシ経由なので直接は通信しない。キャッシュDNSサーバへは内部DNSサーバが転送し、メール中継サーバへはメールサーバが中継する。したがって PC から見て宛先の場所が変わるのは、プロキシサーバ、メールサーバ、内部DNSサーバの3つで、これらへの経路が IPsec ルータ2 向けに変わる。

### 必要な知識

- デフォルトゲートウェイ、ルーティング、サブネット表記：[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)（4. ネットワーク層：IPアドレスとサブネット／6. ルーティング）
- DNS（権威・キャッシュ）、NAT、DHCP：[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)（8. ネットワークを支えるプロトコル：ARP・ICMP・DHCP・DNS・NAT）
- ポート番号（25/53/80/443）と FW のルール：[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)（7. トランスポート層：TCP・UDP・ポート番号）
- オープンリレーと OP25B：[情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)（8. メールセキュリティ）
- IPsec VPN とクラウド接続：[情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)（6. 通信の保護（TLS・VPN・IPsec・無線LAN））

### 採点講評のポイント

全体の正答率は平均的。設問1(2)は低く、OP25B を説明した誤答が目立った（OP25B はオープンリレー防止ではない）。設問2(2)はやや低く、移行後も業務の運用方法とPCの操作が変わらないことを踏まえて解答してほしいとされた。

### この問題から学ぶこと

ネットワーク移行の問題では「誰が誰と直接通信するか」を本文の運用形態から整理し、その一覧をもとに FW ルール・NAT・経路の変更点を導く。NAT の対応は範囲の記述だけでなく、サーバ名とアドレスの表で1対1に確認する。メールの中継（オープンリレー）と OP25B の違いは頻出である。

## 令和6年度秋期 問5「セキュアWebゲートウェイサービスの導入」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/m42obm000000afqx-att/2024r06a_ap_pm_qs.pdf)（24〜28 ページ）
- 難易度：★
- 出題趣旨：セキュア Web ゲートウェイサービスを社内ネットワークへ適用する検討を題材に、ネットワークの変更設計や運用管理の知識を問う。

### 状況設定

人材紹介業の E 社は、DMZ にプロキシサーバと DNS サーバを置き、内部セグメントの PC からのインターネット向け HTTP/HTTPS 通信をプロキシ経由で中継している。業務拡大に伴い、プロキシサーバに代えて Z 社が SaaS として提供するセキュア Web ゲートウェイサービス（サービス Z）の導入を検討することになった。G 主任は、PC にソフト C を導入してサービス Z 経由で通信させる構成案を作り、FW の許可ルールや Y 社 SaaS のアクセス制限設定の見直しを整理した。

### 設問と解き方

#### 設問1(1) a

- **問われていること**：プライベート IP アドレスをグローバル IP アドレス及びポート番号に変換するルータの機能（英字4字）
- **解答例**：NAPT

**解き方**：空欄の直後に『プライベート IP アドレスをグローバル IP アドレス及びポート番号に変換』とある。IP アドレスだけでなくポート番号も変換して多数の端末で1つのグローバルアドレスを共用するのは NAPT（IP マスカレード）。アドレスだけの NAT（3字）と区別する。

#### 設問1(2)

- **問われていること**：下線①：Y社 SaaS がアクセスを許可する送信元 IP アドレス（図1の字句）
- **解答例**：ip1

**解き方**：E 社内からインターネットへ出る通信は、ルータの NAPT で送信元がルータのグローバルアドレスに変換される。図1でルータのインターネット側のアドレスは ip1。したがって Y 社 SaaS から見える送信元は ip1 であり、これを許可しておく。プロキシの ip3 と答えないよう、変換が最後にどこで行われるかを追う。

#### 設問2(1) b

- **問われていること**：悪意のある Web サイトかどうかを評価する際に使うアクセス先の情報（英字3字）
- **解答例**：URL

**解き方**：空欄の後に『や IP アドレスから悪意のある Web サイトであるかどうかを評価』とあり、アクセス先を表す情報で英字3字のものは URL。URL フィルタリング／レピュテーションの考え方と結び付ける。

#### 設問2(2)

- **問われていること**：下線②：受け取ったプログラムを保護された領域で動作させて確認する機能の名称（解答群）
- **解答例**：ウ

**解き方**：『プログラムを保護された領域で動作させ、不正な操作のおそれがないか確認』は、隔離環境で実際に動かして振る舞いを見るサンドボックスの説明そのもの。アンチウイルスはパターン照合が中心で、隔離実行の説明とは一致しない。

#### 設問3(1) c

- **問われていること**：FW で許可する宛先、かつソフト C の通信設定で宛先にする IP アドレス（図2の字句）
- **解答例**：ip8

**解き方**：導入後は PC のインターネット向け Web アクセスはすべてソフト C からサービス Z を経由する（ソフト C→サービス Z は HTTPS）。したがって PC が直接通信する宛先はサービス Z だけになる。図2で Z 社 SaaS の IP アドレスは ip8。

#### 設問3(2) d

- **問われていること**：PC のプロキシ設定で、これまでどおり直接 HTTP 通信できるように設定する対象（図2の機器名）
- **解答例**：業務サーバ

**解き方**：冒頭で、従業員は HTTP でサーバセグメントの業務サーバに直接アクセスしていると書かれている。社内の業務サーバ宛てまでソフト C（サービス Z）経由にすると届かなくなるので、プロキシの例外として直接通信させる。

#### 設問4 e

- **問われていること**：表1（導入前）の FW 許可ルールで、内部セグメントの宛先かつインターネット向け通信の送信元になるもの
- **解答例**：プロキシサーバ 又は ip3

**解き方**：導入前は『PC の Web ブラウザからインターネットへの HTTP/HTTPS はプロキシサーバ経由だけを許可』。よって項番1・2は内部セグメント→プロキシサーバ（443/80）、項番3・4はプロキシサーバ→インターネット（443/80）となる。図1のプロキシサーバのアドレス ip3 でもよい。

#### 設問4 f

- **問われていること**：表2（導入後）の FW 許可ルールのポート番号
- **解答例**：443

**解き方**：ソフト C からサービス Z へは HTTPS 通信を用いる（〔サービス Z の概要〕）。HTTPS のポートは TCP/443。社内の業務サーバ向け HTTP は FW を通らない（L3SW で折り返す）ので、FW では 443 だけ許可すればよい。

### 必要な知識

- NAT／NAPT、ポート番号（HTTP 80 / HTTPS 443）（[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)）
- ファイアウォールのルールとステートフルパケットインスペクション、プロキシサーバ（[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)）
- セキュア Web ゲートウェイ（SWG）、URL フィルタリング、サンドボックス、TLS の復号検査（[情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)）

### 採点講評のポイント

全体の正答率は高かった。設問1(2)はやや低く、送信元 IP アドレスによるアクセス制限はネットワークセキュリティの基本として理解してほしいとされた。設問2(1)もやや低く、危険サイトの判別に URL や IP アドレスが使われることを理解してほしいと指摘された。

### この問題から学ぶこと

ネットワーク構成の変更問題は、通信の始点から終点までを図で指でたどり、どこでアドレス変換されるか・どの機器を経由するかを確認すれば解ける。導入前後で『誰が誰に、どのポートで』通信するかを表にすると FW ルールの空欄が埋めやすい。

## 令和6年度春期 問5「クラウドサービスを活用した情報提供システムの構築」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/m42obm000000afqx-att/2024r06h_ap_pm_qs.pdf)（30〜33 ページ）
- 難易度：★★
- 出題趣旨：IoT機器からクラウドサービスにデータを収集・分析して情報提供するシステムを題材に、IoT機器に適した通信プロトコルの特徴や、通信量が増加した際の処理遅延対策の基本的な理解を問う。

### 状況設定

気象情報を提供するL社は、全国に設置するIoT機器から気象データを収集し、S社クラウドで分析して提供する新システムを構築する。S社クラウド上にはデータ収集用・データ分析用・情報提供用の3台のサーバとFWがある。Mさんは、IoT機器向けの通信プロトコルの選定、インターネットからアクセス可能な機器を最小限にするFWの許可ルール、IoT機器や情報提供先の増加に備えた処理遅延対策を検討した。

### 設問と解き方

#### 設問1(1)

- **問われていること**：全国のIoT機器からデータ収集用サーバに送信される1時間当たりの最大の気象データ量（Mバイト）を答える。
- **解答例**：300

**解き方**：〔データ収集APIに用いる通信プロトコルの検討〕の条件を使う。10,000台 × 500バイト（1件当たり最大）× 60回（1分ごとに1件、1時間で60件）= 300,000,000バイト。1Mバイト = 1,000,000バイトなので 300Mバイト。

#### 設問1(2)

- **問われていること**：下線②「TCP上でHTTPよりプロトコルヘッダサイズが小さく、多対1通信に対応するプロトコル」の略称を答える。
- **解答例**：MQTT

**解き方**：IoT向けの軽量プロトコルで、TCP上で動き、ヘッダが最小2バイトと小さく、ブローカを介した出版・購読（Publish/Subscribe）型で多数の機器からの送信を一か所で受けられるのがMQTT。CoAPもIoT向けだがUDP上で動くので「TCP上で」の条件で外れる。

#### 設問2(1) a

- **問われていること**：表2項番2（インターネット→S社クラウド、TCP/443）の宛先を答える。
- **解答例**：200.a.b.13

**解き方**：インターネット側からアクセスが必要なのは、IoT機器→データ収集用サーバ（項番1、MQTTなので省略）と、情報提供先アプリ→情報提供用サーバの二つ。情報提供APIはWeb APIなのでHTTPS（TCP/443）。図1で情報提供用サーバのアドレスは200.a.b.13。データ分析用サーバ（.12）は外部から直接アクセスされないので許可しない（アクセス可能な機器を最小限にする方針）。

#### 設問2(1) b

- **問われていること**：表2項番3〜5（L社→S社クラウド、TCP/22）の送信元を答える。
- **解答例**：200.c.d.101

**解き方**：設計方針の2点目「L社の保守用PCから各サーバへのアクセスはSSHだけを許可」から、送信元はL社の保守用PC。図1でそのアドレスは200.c.d.101。TCP/22がSSHであることも確認できる。

#### 設問2(1) c

- **問われていること**：表2項番6〜8（S社クラウド→インターネット）のプロトコル／宛先ポート番号を答える。
- **解答例**：TCP/443

**解き方**：設計方針の3点目に「各サーバからインターネットへのアクセスは…任意のWebサイトへのHTTPSだけを許可」とある。HTTPSはTCPの443番ポート。宛先がanyになっているのも「任意のWebサイト」と一致する。

#### 設問2(2)

- **問われていること**：保守用PCを使ってデータ分析用サーバのOS等の更新ファイルを取得・適用する場合に許可されるルールの項番を全て答える。
- **解答例**：4，7

**解き方**：通信の流れを二つに分ける。(1)保守用PCからデータ分析用サーバ（200.a.b.12）へSSHでログイン → 項番4。(2)ログインしたデータ分析用サーバからソフトウェアベンダーのWebサイトへHTTPSで更新ファイルをダウンロード → 送信元200.a.b.12の項番7。応答パケットはステートフルインスペクション（注記1）で自動的に通過するので、戻りのルールは不要。

#### 設問3(1) d

- **問われていること**：データ収集機能と情報提供機能の両方の通信が経由する構成要素名を図1から答える。
- **解答例**：FW

**解き方**：本文の直前の2文で、IoT機器の通信も情報提供先アプリの通信も「S社クラウドのFWを経由して」各サーバにアクセスすると書かれている。両方が共通して通るのは図1のFWだけ。

#### 設問3(2) e

- **問われていること**：「単位時間内に処理できる通信の量」を表す指標を選ぶ。
- **解答例**：ウ

**解き方**：単位時間当たりに処理できるデータ量・処理量はスループット（ウ）。用語の定義そのものなので、解答群から定義に合うものを選ぶ。

#### 設問3(2) f

- **問われていること**：「同時に処理できる接続元の数」を表す指標を選ぶ。
- **解答例**：ア

**解き方**：FWのようなステートフルな機器が同時に保持・処理できる接続の数は（同時）コネクション数（ア）。IoT機器や情報提供先が増えると接続元が増えるので、FWの性能指標として管理する必要がある。

#### 設問3(3)

- **問われていること**：下線③「スケールアウトによってシステムの処理性能を高めるために必要な機能」の名称を選ぶ。
- **解答例**：エ

**解き方**：スケールアウトはサーバの台数を増やして処理を分散させる方式で、複数台のサーバに要求を振り分ける仕組みが必要になる。それがロードバランサー（負荷分散装置、エ）。IDS・WAFはセキュリティ、NASはストレージで、処理能力の分散とは関係しない。

### 必要な知識

- [ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)：MQTTなどIoT向けプロトコル、ポート番号（SSH 22、HTTPS 443）、データ量の単位計算
- [情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)：FWのパケットフィルタリング、ステートフルインスペクション
- [システム構成要素](../../01_テクノロジ系/04_システム構成要素.md)：スループット、スケールアウトとロードバランサー

### 採点講評のポイント

全体として正答率は平均的。設問1(2)は正答率が低く、HTTPに加えてIoT機器の性能や用途に適した通信プロトコルの特性を理解してほしいとされた。設問3(2)は正答率が高かった。

### この問題から学ぶこと

FWルールの問題は「誰が・どこへ・何のプロトコルで」の3点を、本文の設計方針の箇条書きから一つずつ表に写していけば機械的に解ける。経路を問われたら、通信を往路の区間ごとに分けて考え、ステートフルかどうかの注記で戻りの扱いを決める。

## 令和5年度春期 問5「Webサイトの増設」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/ps6vr70000010d6y-att/2023r05h_ap_pm_qs.pdf)（28〜31 ページ）
- 難易度：★★
- 出題趣旨：DNSラウンドロビンを利用したWebサイトの負荷分散を題材に、DNSの仕組みや動作について問う。

### 状況設定

F社はb-DCのWebサイトb（WebAPサーバb、DNSサーバb、FWb）でMシステムを顧客に提供し、F社の運用PCは広域イーサ網経由で運用を行う。DNSサーバbは公開用ドメインexample.jpと社内向けドメインf-sha.example.lanのゾーン情報を管理し、FWbで静的NATを行う。応答遅延の原因がWebAPサーバbの処理能力不足と判明したため、c-DCに同一構成のWebサイトcを構築し、DNSラウンドロビンで負荷分散する。DNSサーバbをプライマリ、cをセカンダリとし、メンテナンス時はAレコードを無効化してから作業する手順も検討した。

### 設問と解き方

#### 設問1(1)

- **問われていること**：下線①：L3SWのデフォルトルートのネクストホップとなる機器（図1中の名称）
- **解答例**：FWf

**解き方**：L3SWの経路表には「b-DCのWebサイトbへの経路」が個別に登録されているので、それ以外の宛先、つまりインターネット向けの不特定な宛先がデフォルトルートでまとめられる。図1でF社からインターネットへ出る出口はFWfなので、ネクストホップはFWf。

#### 設問1(2)

- **問われていること**：下線②の設定で運用PCからDNSサーバbにアクセスするとき経由する機器（図1中の名称、全て）
- **解答例**：L3SW，FWb，L2SWb

**解き方**：運用PCに登録されているのはnsb.f-sha.example.lan、表1から192.168.0.1（DMZのプライベートアドレス）である。プライベートアドレスはインターネット経由では届かないので、L3SWの「Webサイトbへの経路」に従って広域イーサ網を通り、FWb→L2SWb→DNSサーバbと進む。広域イーサ網はサービス網であって図1中の機器ではないので含めない。

#### 設問2(1) a

- **問われていること**：空欄a：顧客と同じURLのFQDN
- **解答例**：miap.example.jp

**解き方**：顧客はインターネットから利用するので、インターネットに公開するドメインexample.jpのFQDNを使う。表1のWebAPサーバbのうちexample.jpの行はmiap.example.jp（グローバルアドレス200.a.b.2）。

#### 設問2(2)

- **問われていること**：下線③：広域イーサ網経由でログインしたWebAPサーバbのFQDN
- **解答例**：apb.f-sha.example.lan

**解き方**：広域イーサ網経由ではDMZのプライベートアドレスで直接アクセスするので、社内向けドメインf-sha.example.lan側の名前を使う。表1でWebAPサーバbのf-sha.example.lanの行はapb.f-sha.example.lan（192.168.0.2）。

#### 設問3(1) b

- **問われていること**：空欄b：運用PCに代替DNSサーバとして登録するもの
- **解答例**：DNSサーバc

**解き方**：優先DNSサーバ（DNSサーバb）が使えないときに備えて代替を登録する。増設構成ではDNSサーバcがセカンダリとして同じゾーン情報をもつので、これを代替DNSサーバに登録すれば「DNSサーバcも利用できる」状態になる。

#### 設問3(1) c

- **問われていること**：空欄c：DNSサーバbの更新内容をcにコピーする設定
- **解答例**：ゾーン

**解き方**：プライマリDNSサーバのゾーン情報をセカンダリDNSサーバに複製する仕組みをゾーン転送という。本文の「DNSサーバbの情報を更新すると、その内容がDNSサーバcにコピーされる」がゾーン転送の説明になっている。

#### 設問3(1) d

- **問われていること**：空欄d：メンテナンス前にDNSサーバbのリソースレコードで小さい値にするもの
- **解答例**：TTL

**解き方**：表1注記2で各リソースレコードのTTLは604800秒（7日）とある。TTLはキャッシュDNSサーバが応答を保持してよい時間なので、このままだとAレコードを無効化しても顧客側のキャッシュが最長7日残り、停止するサイトへのアクセスが続く。事前にTTLを小さくしておけば、無効化が早く反映される。

#### 設問3(2)

- **問われていること**：下線④：メンテナンス中、一つのWebサイトでサービスを提供することによる顧客への影響（25字以内）
- **解答例**：Mシステムの応答速度が低下することがある。

**解き方**：そもそもWebサイトを増設したのは、WebAPサーバbの処理能力不足でMシステムの応答が遅くなったため（〔Mシステムの応答速度の低下〕）。メンテナンス中は片方のサイトに全アクセスが集中し、増設前と同じ状態に戻るので、応答速度が低下するおそれがある。

#### 設問3(3)

- **問われていること**：下線⑤：Aレコードを無効化したWebAPサーバについて確認する内容（20字以内）
- **解答例**：ログイン中の利用者がいないこと

**解き方**：〔Mシステムの構成と運用〕にMシステムの利用にはログインが必要とある。DNSのキャッシュが更新されて新規のアクセスが来なくなっても、それ以前からログインして利用中の顧客はそのサーバとのやり取りを続けている。作業を早く始めすぎると彼らに迷惑を掛けるので、ログイン中の利用者がいなくなったことを確認してから作業を始める。

### 必要な知識

- [ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)：DNS（ゾーン、プライマリ／セカンダリ、ゾーン転送、TTL、Aレコード）、DNSラウンドロビン
- [ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)：デフォルトルート、NAT、DMZ、プライベートアドレスとグローバルアドレス

### 採点講評のポイント

全体の正答率は平均的だった。設問1は(2)が高かったが(1)はやや低く、デフォルトルートが宛先不定のパケットの転送先をまとめた経路であることの理解が求められた。設問3(1)のcは低く、DNSの管理領域がゾーン、その複製がゾーン転送であることを覚えてほしいとされた。設問3(3)も低く、DNSキャッシュが更新されても更新前からログインしている顧客は影響を受けることの理解が求められた。

### この問題から学ぶこと

DNSの問題は「誰が・どのドメイン名で・どこから」アクセスするかで、公開用FQDNと社内用FQDN、グローバルとプライベートのアドレスを使い分けて考える。DNSを書き換えても既存のキャッシュや確立済みのセッションはすぐには切り替わらない、という時間差の視点が記述問題で問われやすい。

## 令和4年度春期 問5「ネットワークの構成変更」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt80000009sgk-att/2022r04h_ap_pm_qs.pdf)（24〜28 ページ）
- 難易度：★★
- 出題趣旨：SaaS利用拡大に伴う通信経路の変化を題材に、ファイアウォールへの通信負荷集中を避ける方策について、TCP/IP通信の基本技術の理解を問う。

### 状況設定

P社は本社と営業所をIPsecルータによるインターネットVPNで接続し、本社のISサーバとQ社のSaaS（Mサービス）を利用している。インターネットやMサービスへの通信はDMZのプロキシサーバ経由で行う。ISサーバを廃止してQ社のGサービスへ移行したところ、FWのセッション情報が増えて応答速度が低下したため、q-SaaS（M・Gサービス）宛ての通信はプロキシを経由せず、各拠点のIPsecルータから直接インターネットへ出すよう経路を変更する。

### 設問と解き方

#### 設問1(1) 宛先

- **問われていること**：営業所のNPCがMサービスを利用するとき、図2の（あ）を通過するパケットの宛先IPアドレスが示す機器
- **解答例**：プロキシサーバ

**解き方**：NPCのブラウザにはプロキシサーバのFQDNが設定されているので、NPCが送るHTTPS通信はMサービスではなくプロキシサーバ宛てになる（プロキシが改めてMサービスへ接続する）。図2で（あ）はFW→プロキシサーバの区間なので、宛先はプロキシサーバ。

#### 設問1(1) 送信元

- **問われていること**：同じパケットの送信元IPアドレスが示す機器
- **解答例**：営業所のNPC

**解き方**：営業所NPC→IPsecルータ2→IPsecルータ1の区間は IPsec トンネルでカプセル化されるだけで、元のパケットの送信元は書き換わらない。IPsecルータ1で取り出されたパケットはL3SW・FWを経てプロキシへ届くので、送信元は営業所のNPCのまま。IPsecルータを答える誤りが多かった（採点講評）。

#### 設問1(2)

- **問われていること**：外出先のNPCからインターネット上のWebサーバにアクセスするとき、L2SW以外で経由する社内の機器（全て）
- **解答例**：ルータ，FW，プロキシサーバ

**解き方**：〔設定内容と動作〕で、外出先NPCもインターネットへのアクセスはプロキシサーバ経由と定められている。図2下段の矢印をたどると、外出先NPC→ルータ→FW→プロキシサーバ→FW→ルータ→Webサーバ。重複を除いて社内の機器を列挙する。

#### 設問1(3) a

- **問われていること**：表1項番1：インターネット→DMZ の DNS（53番）通信の宛先
- **解答例**：外部DNS サーバ

**解き方**：プロトコルが TCP/53・UDP/53（DNS）。インターネットから来るDNS問合せを受けるのは、DMZのサーバのグローバルIPアドレスを管理している外部DNSサーバ。

#### 設問1(3) b

- **問われていること**：表1項番4：DMZ→インターネット の HTTP/HTTPS（80/443）通信の送信元
- **解答例**：プロキシサーバ

**解き方**：NPCのWebアクセスはプロキシサーバが代理でインターネットへ中継する。DMZからインターネットへ80・443番で接続を開始するのはプロキシサーバ。

#### 設問1(3) c

- **問われていること**：表1項番5：内部LAN→DMZ の外部DNSサーバ宛て DNS 通信の送信元
- **解答例**：社内DNS サーバ

**解き方**：NPCは社内DNSサーバで名前解決し、社内DNSサーバは管理外の名前の問合せを外部DNSサーバへ転送する（〔設定内容と動作〕）。よって内部LANから外部DNSサーバへDNS問合せを送るのは社内DNSサーバ。

#### 設問2

- **問われていること**：下線①（プロキシ例外設定に登録されているFQDN）をもつ機器又はサーバ（図1中の名称）
- **解答例**：IS サーバ

**解き方**：〔設定内容と動作〕に「社内のNPCからISサーバへのアクセスは、プロキシサーバを経由せずに直接行う」とある。プロキシを経由させない宛先はブラウザのプロキシ例外設定に登録するので、そこにあるFQDNはISサーバのもの。ISサーバ廃止で不要になる。

#### 設問3(1)

- **問われていること**：下線②でL3SWの経路表に追加する経路（“q-SaaS”を用いて40字以内）
- **解答例**：q-SaaS 宛ての通信のネクストホップがIPsec ルータ1 となる経路

**解き方**：図4では本社NPC→L3SW→IPsecルータ1→q-SaaS。変更前、L3SWはインターネット宛ての通信をFW方向（既定経路）へ送っていた。q-SaaS宛てだけをIPsecルータ1へ向けるには、宛先が q-SaaS のネットワークでネクストホップが IPsecルータ1 という経路を追加する。経路表の要素（宛先・ネクストホップ）で表現するのがコツ。

#### 設問3(2) d

- **問われていること**：表2項番1：NAPT後にインターネットへ転送する HTTPS 通信の宛先
- **解答例**：q-SaaS

**解き方**：IPsecルータ1は本社・営業所からの q-SaaS 宛て HTTPS を、VPNを通さず NAPT してインターネットへ出す役割に変わった。よって宛先は q-SaaS。

#### 設問3(2) e

- **問われていること**：表2項番2：インターネットVPNに転送する通信の宛先
- **解答例**：営業所LAN

**解き方**：IPsecルータ1でVPNに入れるのは、本社から営業所へ向かう通信（ISサーバ廃止後も拠点間の通信は残る）。本社側から見た VPN の向こう側は営業所LAN なので、宛先は営業所LAN。採点講評でも e の正答率が低かったと指摘されている。

### 必要な知識

- プロキシサーバ・DNSの転送・FWのルール（[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)、[情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)）
- IPsec VPN（トンネルモード）とNAPT（[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)、[情報セキュリティ](../../01_テクノロジ系/08_情報セキュリティ.md)）
- ルーティングと経路表（ネクストホップ）（[ネットワーク](../../01_テクノロジ系/07_ネットワーク.md)）

### 採点講評のポイント

全体の正答率は平均的。設問1(1)の送信元はやや低く、IPsecルータ1・2を挙げる誤りが多かった。トンネリングでは送信元IPアドレスが変わらないことを理解してほしいとされた。設問3(1)はやや低く、経路表の経路情報の理解を深めるよう求められた。設問3(2)はdは高いがeが低かった。

### この問題から学ぶこと

ネットワーク問題では、図2・図4のような経路図を指でたどり、各区間でパケットの宛先・送信元が何になるか（プロキシ、NAPT、トンネル）を意識することが基本。FWルール表は“どのサーバが誰と何のプロトコルで話すか”を本文の動作説明と対応付ければ埋まる。
