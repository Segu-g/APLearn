## 令和7年度秋期 問3「二つの列の最長共通部分列（Longest Common Subsequence）の長さを求めるアルゴリズム」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_ap_pm_qs.pdf)（18〜22 ページ）
- 難易度：★
- 出題趣旨：最長共通部分列問題を題材に、部分問題に場合分けして動的計画法で効率的に解くアルゴリズムの理解と、それをプログラムとして実装する力を問う。

### 状況設定

二つの文字の列 X、Y の最長共通部分列（順序を保って両方から抽出できる最長の列）の長さ LCSL(n, k) を求める。末尾の要素 x_n と y_k が一致するかどうかで3つの場合に分けた再帰的な関係を示す。そのうえで、同じ計算の重複を避けるため、二次元配列 lcsl に値を表として埋めていく動的計画法のプログラム（図4）を完成させ、時間計算量を答える。

### 設問と解き方

#### 設問1

- **問われていること**：列{A, C, B, C, D, C}と列{C, D, B, D, C, A}の最長共通部分列の長さ。
- **解答例**：4

**解き方**：X=ACBCDC、Y=CDBDCA として共通部分列を探す。例えば C, B, D, C は、Xでは2・3・5・6番目、Yでは1・3・4・5番目から順序を保って取り出せる。5文字の共通部分列があるか確かめると、YでCの後にDを2回含む並び（C, D, B, D, C など）はXにDが1つしかないため作れない。図3と同じ要領で表を埋めても、右下の LCSL(6, 6) は4になる。

#### 設問2 ア

- **問われていること**：図3の LCSL(3, 4) の値。
- **解答例**：2

**解き方**：図3を左上から規則どおりに埋める。n=1（A）の行は k=4（A）で一致して1になり、以降は1。n=2（B）の行は 0,1,1,1,1,2,2。n=3 の x3=C は y3=C と一致するので LCSL(3,3)=LCSL(2,2)+1=2。ア（k=4、y4=A）は x3≠y4 なので max(LCSL(3,3), LCSL(2,4)) = max(2, 1) = 2。

#### 設問2 イ

- **問われていること**：図3の LCSL(7, 5) の値。
- **解答例**：4

**解き方**：続けて行を埋める。n=4（B）の行は 0,1,1,2,2,3,3、n=5（D）の行は 0,1,2,2,2,3,3、n=6（A）の行は 0,1,2,2,3,3,4 となる。イは x7=B、y5=B で一致するので LCSL(7,5)=LCSL(6,4)+1=3+1=4。最終的な LCSL(7,6) も4で、本文の「長さが4」と一致することで検算できる。

#### 設問3 ウ

- **問われていること**：S[n−1] と T[k−1] が等しいときに lcsl[n, k] に代入する式。
- **解答例**：lcsl[n － 1, k － 1] ＋ 1

**解き方**：配列の要素番号は0から始まるので、S[n−1] が列の n 番目の要素 x_n、T[k−1] が y_k に当たる。一致する場合は（1）の関係 LCSL(n,k)=LCSL(n−1,k−1)+1 をそのまま配列の書き方に直す。講評では添字の誤りが多かったとされているので、表の左上（斜め）の要素を参照することを確認する。

#### 設問3 エ

- **問われていること**：lcsl[n, k−1] が lcsl[n−1, k] より大きいときに代入する値。
- **解答例**：lcsl[n, k － 1]

**解き方**：一致しない場合は（2）の関係により、LCSL(n, k−1) と LCSL(n−1, k) の大きい方を採る。elseif の条件が「lcsl[n, k−1] が lcsl[n−1, k] より大きい」なので、このときは大きい方である lcsl[n, k−1]（表の左隣）を代入する。

#### 設問3 オ

- **問われていること**：それ以外（lcsl[n, k−1] ≦ lcsl[n−1, k]）のときに代入する値。
- **解答例**：lcsl[n － 1, k]

**解き方**：else に来るのは lcsl[n−1, k] が lcsl[n, k−1] 以上のときなので、最大値は lcsl[n−1, k]（表の上隣）。同じ値のときはどちらを入れても結果は同じである。

#### 設問3 カ

- **問われていること**：関数の戻り値（最長共通部分列の長さ）。
- **解答例**：lcsl[s, t]

**解き方**：求めたいのは列全体どうし（S の s 個、T の t 個）の LCSL なので、表の右下の要素 lcsl[s, t] を返す。図3で LCSL(7, 6) が答えになることと対応している。

#### 設問4 キ

- **問われていること**：図4のプログラムの時間計算量 O(キ)（s と t を用いて）。
- **解答例**：st

**解き方**：初期化の for は O(s) と O(t) で済む。主な処理は n を1〜s、k を1〜t とする二重ループで、内側の処理は定数時間なので、全体の手間は s×t 回に比例する。したがって O(st)。再帰で素直に計算すると同じ部分問題を何度も解くため指数時間になりうるが、動的計画法ならそれを避けられることも押さえておく。

### 必要な知識

- 動的計画法、再帰と計算量（O 記法）：[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)（4. 計算量／5. 再帰）
- 二次元配列と擬似言語の読み方（要素番号が0から始まる点）：[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)（6. 擬似言語の読み方）
- 科目B プログラミング問題の読み方：[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)（7. 科目B「プログラミング」問題の読み方のコツ）

### 採点講評のポイント

全体の正答率は高かった。設問3は平均的で、二次元配列 lcsl の要素番号の誤りが目立ったため、どの要素をどう更新するかを正確に理解してプログラムに書けるようにしてほしいとされた。設問4も平均的で、時間計算量の理解を深めるよう求められた。

### この問題から学ぶこと

動的計画法の問題では、まず小さな表を手で埋めて漸化式の動きを確かめると、プログラムの空欄（斜め・左・上のどれを参照するか）がそのまま分かる。列の番号（1始まり）と配列の要素番号（0始まり）のずれは頻出の落とし穴なので、S[n−1] が x_n に当たることを毎回確認する。

## 令和7年度春期 問3「スライドパズルを幅優先探索で解くプログラム」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07h_ap_pm_qs.pdf)（18〜23 ページ）
- 難易度：★★
- 出題趣旨：スライドパズルの最小手数の解を求める問題を題材に、幅優先探索アルゴリズムの理解と、配列・キュー・リストを使ったプログラムの実装力を問う。

### 状況設定

一辺がNマスのスライドパズルについて、ゴールの盤面になるまでの移動回数が最小になる手順を求める。盤面の遷移を、開始時点の盤面をルートとする木（グラフ）で表し、幅優先探索で子ノードを生成していく。既に探索した盤面と同じ子ノードは終端とし、ゴールと一致したら探索を終える。盤面は二次元配列で表し、空白マスは「最大の駒の数字＋1」で表す。探索対象をキュー、探索済みの盤面をリストで管理するプログラム（図7）の空欄を埋める。

### 設問と解き方

#### 設問1

- **問われていること**：図2の②の盤面（網掛けで隠されている）を図3にならって配列で表す
- **解答例**：{{8, 6, 7}, {2, 9, 4}, {3, 5, 1}}

**解き方**：ルートノードでは、空白マスは3行目2列目にあります。空白の上下左右にある駒は、上が5、左が3、右が1の三つです。①は3（左の駒）を、③は1（右の駒）を動かした盤面なので、残る②は上の5を下へ動かした盤面です。5が3行2列目に移り、空白が2行2列目に移ります。図3の決まりでは、N＝3のとき空白マスは8＋1＝9で表すので、2行目は{2, 9, 4}、3行目は{3, 5, 1}になります。図2で②の子ノード⑥〜⑨の盤面（空白が2行目の周りにある）とも矛盾しないことを確かめておきましょう。

#### 設問2 ア

- **問われていること**：while文の継続条件（キューが空でない間繰り返す）
- **解答例**：explore_queue.isEmpty()

**解き方**：幅優先探索は、キューから探索対象を1つずつ取り出しては子ノードをキューに追加する処理を繰り返し、探索対象がなくなったら終わります。行44で「移動方法がない旨」を出力していることからも、while文を抜けるのは「キューが空になったとき」です。条件が「（ア）がfalseと等しい」という形なので、アには空かどうかを判定する式 explore_queue.isEmpty() を入れます。

#### 設問2 イ

- **問われていること**：キューから探索対象の盤面を取り出すメソッド
- **解答例**：poll()

**解き方**：行21では、これから子ノードを作る盤面をstateに代入しています。図5のQueueには先頭を「取り出して返す」poll()と、取り出さずに「返す」だけのpeek()があります。peek()ではキューから要素が減らず、同じ盤面を何度も処理し続けてしまうため、poll()を選びます。

#### 設問2 ウ

- **問われていること**：空白マスの移動後の行番号を求めるときに加える値
- **解答例**：direction[i][1]

**解き方**：行4のコメントに、directionは移動方向を「行番号の増減を1番目の要素、列番号の増減を2番目の要素」で表す配列だと書かれています。行28で新しい空白の行番号を「現在の行番号＋ウ」で求めているので、ウはi番目の方向の行の増減 direction[i][1] です。配列の要素番号は1から始まる点に注意します。

#### 設問2 エ

- **問われていること**：移動後の空白マスが盤面内にあるかを判定する上限値
- **解答例**：board_size

**解き方**：行23〜26は、移動後の空白マスの行番号と列番号がどちらも「1以上かつエ以下」であること、つまり盤面からはみ出さないことを確かめています。盤面は一辺board_sizeマスの正方形なので、行番号と列番号の上限はどちらもboard_sizeです。行31に出てくる board_size × board_size は空白マスを表す値で、範囲の上限ではありません。採点講評で正答率が低いとされたのはこの取り違えです。

#### 設問2 オ

- **問われていること**：空白マスの移動後の列番号を求めるときに加える値
- **解答例**：direction[i][2]

**解き方**：ウと同じ考え方で、行29は列番号の更新です。directionの2番目の要素が列番号の増減なので、direction[i][2] になります。行25〜26の範囲チェックも、列について同じ値を使っています。

#### 設問2 カ

- **問われていること**：新しく作った盤面がゴールかどうかを判定する式
- **解答例**：checkGoal(new_state.board, goal_board)

**解き方**：条件がtrueのときに printResult を呼んで終了しているので、ここはゴールの判定です。表2の checkGoal(b, g) は、第1引数の盤面配列と第2引数のゴールの盤面配列が一致するかを返します。駒を動かした後の盤面 new_state.board と、行12で作った goal_board を渡します。

#### 設問2 キ

- **問われていること**：探索済みでない新しい盤面をキューに追加する処理
- **解答例**：add(new_state)

**解き方**：行37の条件は「探索済みの盤面と一致しない」場合なので、新しい盤面を次の探索対象としてキューへ入れます。Queueのadd()はBoardStateへの参照を受け取るので、盤面配列ではなく new_state 自体を渡します。BoardStateのprevでたどれるようにしておくことで、最後にprintResultで手順を出力できます。

#### 設問2 ク

- **問われていること**：新しい盤面を探索済みのリストに登録する処理
- **解答例**：add(new_state.board)

**解き方**：行19で開始時点の盤面配列を check_list に登録しているのと同じように、新しく見つけた盤面も探索済みとして登録します。図6のListのadd()は盤面配列（整数型配列の配列）を受け取るので、引数は new_state ではなく new_state.board です。キとクで引数の型が違うことを、図5と図6で必ず確認しましょう。

### 必要な知識

- [幅優先探索と深さ優先探索](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：キューを使い、浅いノードから順に調べるので、最初に見つかったゴールが最小手数になる

### 採点講評のポイント

## 令和6年度秋期 問3「素数を列挙するアルゴリズム」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/m42obm000000afqx-att/2024r06a_ap_pm_qs.pdf)（14〜17 ページ）
- 難易度：★★
- 出題趣旨：エラトステネスの篩を題材に、素数の性質（倍数の除外、偶数の除外）を利用したアルゴリズムの効率化の理解を問う。

### 状況設定

N 以下の素数を列挙する関数 prime1 は、各 d について 2〜d−1 で割り切れるかを全て調べる素朴な方法である。prime2 は素数 d が見つかるたびに d×d 以上の d の倍数を『素数ではない』とマークするエラトステネスの篩である。prime3 はさらに奇数だけを扱い、isPrime[k] で 2k+1 が素数かを表すことで、ループ回数と配列の要素数を半分以下にする。

### 設問と解き方

#### 設問1 ア

- **問われていること**：prime1 の時間計算量（N を用いて）
- **解答例**：N²

**解き方**：図1は外側の while で d を 2〜N まで回し、内側の while で t を 2〜d−1 まで回す二重ループ。(L1) の実行回数は Σ(d−2) ≒ N²/2 なので、オーダーは O(N²)。内側のループに途中終了（break）がないので、素数でも合成数でも毎回 d−2 回回る点に注意。

#### 設問2 イ

- **問われていること**：prime2 で d がまだ『素数である』とマークされているかを判定する条件
- **解答例**：isPrime[d]がtrueと等しい

**解き方**：手順(2)(a)(b)により、d が『素数である』とマークされている場合だけ確定・倍数のマークを行う。isPrime[k] は k が素数かを表す配列なので、条件は isPrime[d] が true であること。

#### 設問2 ウ

- **問われていること**：d の倍数を順にマークするための t の更新式
- **解答例**：t＋d

**解き方**：t は d×d から始まり、d の倍数を『素数ではない』にしていく。次の倍数は今の t に d を足したものなので t ← t＋d。手順(2)(b)②の『d を x 倍した数（x≧d）』が d×d, d×(d+1), … であることと対応する。

#### 設問3 エ

- **問われていること**：prime3 で奇数 d が素数とマークされているかの判定条件
- **解答例**：isPrime[(d－1)÷2]がtrueと等しい

**解き方**：prime3 では isPrime[k] が 2k+1 を表す（改良2の(3)）。d＝2k+1 を k について解くと k＝(d−1)÷2。したがって isPrime[(d−1)÷2] が true かを調べる。c を 3 から 2 ずつ増やして配列を作っているので k＝1 が 3 に対応することも確認できる。

#### 設問3 オ

- **問われていること**：t（奇数）に対応する isPrime の要素番号
- **解答例**：(t－1)÷2

**解き方**：エと同じ変換を t に適用する。t＝2k+1 なので k＝(t−1)÷2。t は d×d（奇数×奇数＝奇数）から始まり、カで奇数のまま増えるので、常に整数になる。

#### 設問3 カ

- **問われていること**：奇数の倍数だけをたどる t の更新式
- **解答例**：t＋2×d

**解き方**：d の倍数のうち t＋d は『奇数＋奇数＝偶数』となり、偶数は扱わない方針（改良2の(2)）。奇数の倍数だけを飛び石で進むには 2d ずつ足す：d², d²+2d, d²+4d, …。よって t ← t＋2×d。

#### 設問4 (L1)

- **問われていること**：prime1(20) で (L1) が実行される回数
- **解答例**：171

**解き方**：d ごとの内側ループの回数は d−2 回（t＝2〜d−1）。d＝2〜20 の合計は 0＋1＋2＋…＋18 ＝ 18×19÷2 ＝ 171。

#### 設問4 (L2)

- **問われていること**：prime2(20) で (L2) が実行される回数
- **解答例**：13

**解き方**：素数 d について t＝d×d から N 以下まで d ずつ進む回数を数える。d＝2：t＝4,6,8,…,20 → (20−4)÷2＋1＝9回。d＝3：t＝9,12,15,18 → 4回。d＝5 以降は d×d＝25＞20 で0回（d＝4 は合成数で実行されない）。合計 9＋4＝13。

#### 設問4 (L3)

- **問われていること**：prime3(20) で (L3) が実行される回数
- **解答例**：2

**解き方**：奇数の素数 d について t＝d×d から 2d ずつ進む。d＝3：t＝9, 15（次の21は20超え）→ 2回。d＝5：25＞20 で0回。合計 2。prime2 の 13 回から大きく減ることが確認できる。

### 必要な知識

- 時間計算量（オーダー記法）と二重ループの回数の数え方（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）
- 擬似言語のトレース、配列の添字変換（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）
- 素数・倍数・数列の和（1＋2＋…＋n＝n(n+1)/2）（[基礎理論](../../01_テクノロジ系/01_基礎理論.md)）

### 採点講評のポイント

全体の正答率はやや低かった。設問2は正答率が高かった。設問3はやや低く、配列中のデータの保持方法（2k+1 との対応）の理解不足と思われる解答が散見され、ループ中でカウンタ変数がどう変化するかを注意深く考えてほしいとされた。

### この問題から学ぶこと

## 令和6年度春期 問3「グラフのノード間の最短経路を求めるアルゴリズム」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/m42obm000000afqx-att/2024r06h_ap_pm_qs.pdf)（18〜22 ページ）

### 状況設定

### 設問と解き方

#### 設問1 ア

- **問われていること**：表1の4回目・5回目でV5の始点ノード距離を答える。
- **解答例**：17

**解き方**：4回目の更新起点ノードはV3〈14〉。V3に隣接し未確定なのはV5のみで、V3–V5の距離は図1から3。V3経由の距離 = 14 + 3 = 17。現在の値19（V4経由：13 + 6）より小さいので17に更新する。5回目は残ったV5〈17〉が更新起点として選ばれ、終点なので終了。

#### 設問2 イ

- **問われていること**：図2の行15、未確定ノードの中から始点ノード距離が最小のノードを探す条件を答える。
- **解答例**：dist[k]がminDist より小さい

**解き方**：行13〜19は「最小値を求める」定型処理。minDistをINFで初期化し、未確定（done[k]が0）かつ現在の最小値より小さいノードが見つかるたびに、最小値と添字を更新する。したがって条件は「dist[k]がminDistより小さい」。大小を逆にすると最大値を探すことになる。

#### 設問2 ウ

- **問われていること**：行16でminDistに代入する値を答える。
- **解答例**：dist[k]

**解き方**：イの条件が成り立ったら、そのノードの始点ノード距離を新しい最小値として保存し（ウ）、行17でそのノード番号をcurNodeに保存する。よってminDist ← dist[k]。

#### 設問2 エ

- **問われていること**：行25〜26、更新起点ノードを経由した場合の始点ノード距離を表す式を答える。
- **解答例**：dist[curNode] ＋ edge [curNode, k]

**解き方**：手順③は「更新起点ノードを経由した場合の始点ノード距離」を計算し、現在の値より小さければ更新する。経由した場合の距離 = （更新起点ノードまでの最短距離）+（更新起点ノードからノードkへのエッジの距離）= dist[curNode] + edge[curNode, k]。隣接していない場合はedgeがINFなので、条件が成り立たず更新されない。設問1の「14 + 3」を変数に置き換えた式だと考えると確認しやすい。

**解き方**：代入文はdist[k]を更新する場合だけ実行する必要があるので、行25のifの内側に入れる。if文の内側で最も早い位置は「行25の直後」（行26の前）。行26の直後でも動作は同じだが、設問は最も小さい番号を求めているので25。

#### 設問3(2) カ

- **問われていること**：終点のノード番号を起点として何をたどることで、最短経路を逆順に出力するのかを選ぶ。
- **解答例**：ア

#### 設問4(1) キ

- **問われていること**：始点ノード距離の計算が最大N回で、選ぶ回数も最大N回となるものを本文の字句で答える。
- **解答例**：更新起点ノード

**解き方**：行14〜19で全ノード（N個）を調べて選んでいるのは更新起点ノードで、一度選ばれると行20でdoneが1になり確定するので、選ばれる回数は最大N回。本文の〔始点から終点までの最短距離を求める手順〕で定義された用語をそのまま使う。

#### 設問4(2) ク

- **問われていること**：最悪の場合の計算量O(ク)を答える。
- **解答例**：N²

**解き方**：外側のwhileで更新起点ノードを最大N回選び、その1回ごとに内側のforループ（行14と行24）がそれぞれN回まわる。計算量は N ×（N + N）= 2N² で、定数倍を無視してO(N²)。

## 令和5年度秋期 問3「2分探索木とAVL木の回転による平衡化」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/ps6vr70000010d6y-att/2023r05a_ap_pm_qs.pdf)（14〜18 ページ）
- 難易度：★★★
- 出題趣旨：2分探索木の一種である平衡2分探索木のうちAVL木を題材に、木構造、再帰的アルゴリズム、計算量の理解を問う。

### 状況設定

2分探索木を構造体Node（key、left、right）で表し、再帰による探索関数searchと挿入関数insertが示される。偏った木では探索効率が落ちるため、右回転rotateRと左回転rotateLを定義する。全ノードで左右の部分木の高さの差が1以下という条件Balを保つように、挿入後に親をたどりながら回転する関数balanceと、それを組み込んだ挿入関数insertBが示される。

### 設問と解き方

#### 設問1 ア

- **問われていること**：ノード数nの2分探索木を探索するときの最悪時間計算量O(ア)
- **解答例**：n

**解き方**：直後の文に、最悪になるのは「葉を除く全てのノードで左右どちらかにだけ子がある」場合とある。この木は一列につながったリストと同じ形で、高さはnになる。最下段のノードを探すにはn回の比較が必要なので、O(n)である。

#### 設問1 イ

- **問われていること**：完全な2分探索木での最悪時間計算量O(イ)
- **解答例**：log n

**解き方**：全ての葉の深さが等しい完全2分木では、深さが1段増えるごとにノード数が2倍になる。そのため高さはおよそlog₂nである。探索は根から1段ずつ下るだけなので、比較回数は高さに比例してO(log n)になる。

#### 設問2(1) ウ

- **問われていること**：図7関数balanceで、右回転を行う分岐の条件
- **解答例**：h1 が2と等しい

**解き方**：h1＝左の高さ−右の高さである。手順(1)は「左側の部分木が右側より2大きい場合に右回転する」としている。ウの分岐の最後はrotateR(t)になっているので、条件はh1が2と等しい場合である。

#### 設問2(1) エ

- **問われていること**：右回転の前に左の子を左回転するかどうかを判定する値h2の式
- **解答例**：height(t.left.right) - height(t.left.left)

**解き方**：手順(1)の但し書きは、左の子Uについて「Uの右部分木の方がUの左部分木よりも高い場合は、先にUで左回転する」としている。プログラムでは「h2が0より大きい場合にt.leftを左回転」なので、h2はU（＝t.left）の右の高さから左の高さを引いた値にすればよい。引き算の順序を逆にすると条件の向きも逆になるので注意する。

#### 設問2(1) オ

- **問われていること**：左回転を行う分岐の条件
- **解答例**：h1 が-2と等しい

**解き方**：手順(2)は、右側が左側より2大きい場合である。h1は左−右なので、右が2高いときh1は−2になる。分岐の最後がrotateL(t)であることとも合う。

#### 設問2(1) カ

- **問われていること**：左回転の前に右の子を右回転するかどうかを判定する値h3の式
- **解答例**：height(t.right.left) - height(t.right.right)

**解き方**：手順(2)の但し書きは、右の子Vについて「Vの左部分木の方が高い場合は、先にVで右回転する」としている。プログラムは「h3が0より大きい場合にt.rightを右回転」なので、h3はVの左の高さから右の高さを引いた値になる。エと左右を入れ替えた形である。

#### 設問2(2)

- **問われていること**：図1の木（根r）に対してinsertB(insertB(r, 4), 8)を実行した結果の2分探索木を図示する
- **解答例**：（図）根が5，5の左の子が3（3の左の子が1，右の子が4），5の右の子が8（8の左の子が6，右の子が9）

**解き方**：insertBは挿入後、挿入位置から根に向かって各ノードでbalanceを適用する。これを机上で再現する。 ① 4の挿入：6→3→5とたどり、5の左の子になる。5は左右の高さが1と0、3は1と2なので条件Balを満たす。根6では左（3の部分木）の高さが3、右（9）が1でh1＝2になる。h2＝height(5の部分木)−height(1)＝2−1＝1>0なので、先に3を左回転して5(3(1,4),－)にする。次に6を右回転して、根5、左が3(1,4)、右が6(－,9)の木を得る。 ② 8の挿入：5→6→9とたどり、9の左の子になる。9は問題なし。6は左0、右2でh1＝−2になる。h3＝height(8)−height(9の右＝空)＝1>0なので、先に9を右回転して8(－,9)にする。次に6を左回転して8(6,9)にする。根5は左の高さ2、右の高さ2で条件を満たす。 結果は5(3(1,4),8(6,9))となる。最後に、各ノードで左が小さく右が大きいこと（2分探索木の条件）と、高さの差が1以下であることを確認する。講評は、この確認を怠った誤答が多かったと指摘している。

#### 設問2(3) キ

- **問われていること**：条件Balを満たすn個のノードの木にinsertBを実行したときの最悪時間計算量O(キ)
- **解答例**：log n

**解き方**：条件Balを満たす木は、高さがO(log n)に抑えられる（ほぼ左右均等）。insertBは根から挿入位置まで1本の経路を再帰で下り、戻りながら各ノードでbalanceを1回ずつ呼ぶ。balanceの中の回転は最大2回で、参照の付け替えだけの定数時間である（heightの時間は無視してよいと指定がある）。したがって全体は高さに比例し、O(log n)になる。講評は、探索だけでなく挿入時の効率も考えるよう求めている。

### 必要な知識

- [データ構造](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：2分探索木の性質、平衡木（AVL木）、木の高さ
- [計算量](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：O(n)とO(log n)、木の高さと探索回数の関係
- [再帰](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：部分木に対して自分自身を呼ぶ処理の追い方
- [科目B「プログラミング」問題の読み方のコツ](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：本文の手順と擬似コードの対応付け

### 採点講評のポイント

全体の正答率は平均的だった。balanceの空欄（設問2(1)）は正答率がやや高かった。設問2(2)の木の図示は正答率が低く、平衡や2分探索木の条件を満たさない誤答が多かったため、アルゴリズムを机上で再現する力を求めている。挿入の計算量（設問2(3)）も正答率が低かった。

### この問題から学ぶこと

擬似コードの空欄は、本文の手順（日本語）の各文とコードの各行を一対一で対応させれば埋まる。特に引き算の順序と符号に注意する。木の操作を図示する問題は、1回の挿入ごとに図を描き、最後に2分探索木の条件と平衡条件を必ず点検する。

## 令和5年度春期 問3「多倍長整数の演算」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/ps6vr70000010d6y-att/2023r05h_ap_pm_qs.pdf)（16〜20 ページ）
- 難易度：★★★
- 出題趣旨：任意桁数の整数の乗算処理を題材に、多倍長整数の乗算アルゴリズムの一つであるカラツバ法の理解と実装を問う。

### 状況設定

整数を1の位から1次元配列に格納する多倍長整数を扱う。乗算にはカラツバ法を使い、M桁×M桁の式を上位・下位M/2桁ずつに分けたA, B, C, Dから、A×C、B×D、(A+B)×(C+D)の3個の子ノードを作るツリーを最下層（1桁×1桁）まで構築する（図2）。(A+B)などは桁ごとの加算だけ行い、繰り上がりは最後にまとめて処理する。ツリーのノードは配列elementsに層ごとに格納し、各層の先頭位置をlayer_topに持つ。ツリー構築（図3）と、子ノードの結果から式(1)で親を計算する演算（図4）のプログラムの空欄を埋める。

### 設問と解き方

#### 設問1 ア

- **問われていること**：図2の層3の空欄ア（34×78の子ノード①）
- **解答例**：3×7

**解き方**：層2のノード②34×78を、本文〔ツリー構造の構築〕の規則で分ける。左の値34をA=3, B=4、右の値78をC=7, D=8とすると、子ノード①はA×C=3×7（②B×D=4×8、③(A+B)×(C+D)=7×15で、図中の右隣2個と一致することで確認できる）。

#### 設問1 イ

- **問われていること**：図2の層3の空欄イ（46×134の子ノード①）
- **解答例**：4×12

**解き方**：ここが落とし穴。134は普通の3桁の数ではなく、56+78を「桁ごとの加算」だけした結果で、10の位が12、1の位が14という2要素の多倍長整数（values={14, 12}）である。したがって2桁を1要素ずつに分けるとC=12, D=14。左の46はA=4, B=6なので、子ノード①はA×C=4×12。右隣の6×14（B×D）、10×26（(4+6)×(12+14)）とも整合する。

#### 設問2

- **問われていること**：46×134のノードについて式(1)を具体化した計算式の①〜④
- **解答例**：① 48 ② 260 ③ 48 ④ 84

**解き方**：設問1で求めた子ノードの計算結果は α=4×12=48、β=6×14=84、γ=10×26=260。このノードの桁数K=2なので、式(1) α×10^K + (γ−α−β)×10^(K/2) + β は 48×100 + (260−48−84)×10 + 84 となる。与えられた形「(①)×100 + ((②)−(③)−84)×10 + (④)」と照合して ①48、②260、③48、④84。

#### 設問3 ウ

- **問われていること**：各層の先頭インデックスを求める式の空欄ウ
- **解答例**：pow(3, i － 1)

**解き方**：各ノードは子を3個もつので、第i層のノード数は3^(i−1)個（層1が1個、層2が3個、層3が9個）。次の層の先頭位置は「この層の先頭位置＋この層のノード数」なので layer_top[i+1] ← layer_top[i] + pow(3, i−1)。表3の例 {1, 2, 5} で検算すると 1+3^0=2、2+3^1=5 となり一致する。

#### 設問3 エ

- **問われていること**：子ノード①へのインデックスを求める式の空欄エ（図3・図4共通）
- **解答例**：3*(i － 1)

**解き方**：親の層dpで左から i 番目の親ノードを考える。それより左にある i−1 個の親が、それぞれ3個ずつ子を次の層に並べているので、i 番目の親の子ノード①は次の層の先頭から 3×(i−1) 個進んだ位置にある。よって tidx ← layer_top[dp+1] + 3*(i−1)。図2で層2の③（i=3）なら layer_top[3]＋6＝5＋6＝11 となり、elements[11] が層3の7番目のノード イ（4×12）を指すことで確かめられる。

#### 設問3 オ, カ

- **問われていること**：子ノード生成時にleft/right/lraddへ渡す値の空欄オ、カ（順不同）
- **解答例**：オ：pe.val1　カ：pe.val2（順不同）

**解き方**：子ノードは親ノードpeの乗算記号の左右の値を分割して作る。表1でノード構造体の乗算記号の左側はval1、右側はval2なので、left(pe.val1, cn)がA、left(pe.val2, cn)がC、rightがB, D、lraddが(A+B), (C+D) になる。peは構造体の変数なので「構造体変数名.要素名」の形で書くことに注意（val1だけでは大域変数のルートの値になってしまう）。

#### 設問4 キ

- **問われていること**：最下層の乗算結果の1の位を求める式の空欄キ
- **解答例**：mod(mul, 10)

**解き方**：最下層は1桁×1桁なので結果mulは0〜81の2桁以内。次の行で10の位を mul / 10（整数除算）で求めているので、1の位は10で割った余り mod(mul, 10) となる（表3にmod関数が定義されている）。

#### 設問4 ク, ケ

- **問われていること**：γ−α−β を計算する式で、s1 ← sub(ク.result, ケ.result) の空欄
- **解答例**：ク：elements[cidx ＋ 2]　ケ：elements[cidx]

**解き方**：子ノードは elements[cidx]＝①（α）、elements[cidx+1]＝②（β）、elements[cidx+2]＝③（γ）の順に並ぶ。次の行で s2 ← sub(s1, elements[cidx+1].result) とβを引いているので、s1ではγ−αを計算すればよい。subは p−q を返すので、第1引数がγ（elements[cidx+2]）、第2引数がα（elements[cidx]）。

#### 設問5

- **問われていること**：N桁同士の乗算で、配列valuesに必要な最大の要素数（Nを用いて）
- **解答例**：2 × N

**解き方**：N桁×N桁の積は最大で2N桁になる（例：99×99=9801は4桁）。ルートノードのresultは、繰り上がり処理の後に最終的な答えを格納するので、2N個の要素が必要。途中の (A+B) などは桁ごとの加算だけで要素数は増えないため、最大は結果側で決まる。

### 必要な知識

- [アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)：配列による木構造の表現、擬似言語の読み方、再帰的な分割統治
- [基礎理論](../../01_テクノロジ系/01_基礎理論.md)：位取り記数法、桁上がりの処理

### 採点講評のポイント

全体の正答率は平均的だった。設問3のエは正答率が低く、ツリー構造を1次元配列で管理する手法とその添字計算を理解してほしいとされた。オ・カもやや低く、構造体の扱い方とツリーの情報構造の両方を理解して注意深く解答する必要があった。

### この問題から学ぶこと

配列で木を表すときの添字計算は「左にある兄弟の数×子の数」で考え、必ず図の具体例（表3の{1, 2, 5}など）に当てはめて検算する。桁ごとの加算だけした値（134＝{14,12}）のように、問題独自のデータ表現に引っかけがあるので、本文の定義を見落とさないこと。

## 令和4年度秋期 問3「迷路の探索処理」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt80000008smf-att/2022r04a_ap_pm_qs.pdf)（16〜19 ページ）
- 難易度：★★★
- 出題趣旨：迷路の探索処理を題材に、同じ処理を繰り返して解を探索する再帰関数を用いたアルゴリズムの理解と、プログラムの応用力を問う。

### 状況設定

外壁と障害物のある 5×5 の迷路で、始点から終点までの全ての解（同じマスを 2 回通らない経路）を求める。各マスから y+1、x+1、y−1、x−1 の順に“進む”ことを試し、進めなければ一つ前のマスに“戻る”深さ優先探索を、足跡フラグとスタックを使って再帰関数 visit で実装する。解が一つの迷路（図1）と解が四つある迷路（図2）を例に、移動の過程やプログラムの空欄を考える。

### 設問と解き方

#### 設問1(1)

- **問われていること**：図1 で終点に到達したとき“訪問”されなかったマスの総数
- **解答例**：3

**解き方**：図1 の障害物は (3,5)(4,5)(2,4)(3,3)(4,3)(2,2)(4,1)。①y+1→②x+1→③y−1→④x−1 の順に試して手で追う。(1,1)→(1,2)→…→(1,5)→(2,5) は行き止まりで (1,3) まで戻り、(2,3) も行き止まりで (1,1) まで戻る。次に (2,1)→(3,1)→(3,2)→(4,2)→(5,2)→(5,3)→(5,4)→(5,5) で終点。通れる 18 マスのうち一度も踏まなかったのは (3,4)(4,4)(5,1) の 3 マス。

#### 設問1(2) ア

- **問われていること**：始めから 13 回目の“移動”が終了した時点でスタックに格納されている座標の個数
- **解答例**：2

**解き方**：本文の例の続きを数える。7 回目で (1,4)、8 回目 (1,3) に戻る、9 回目 (2,3) に進む、10 回目 (1,3)・11 回目 (1,2)・12 回目 (1,1) に戻る、13 回目 (2,1) に進む。このときスタックは (1,1)(2,1) の 2 個。戻るたびにスタックから一つ減ることを押さえて数える。

#### 設問2 イ

- **問われていること**：終点到達時にスタックの内容をコピーする代入先
- **解答例**：paths[sol_num][k]

**解き方**：表1 で、全ての解を格納するのは 2 次元配列 paths[u][v]（u は解の番号、v は座標の順番）。for で k を 0 から stack_top まで回して stack_visit[k] を写すので、v に k を、u に“今見つけた解の番号”を入れる。直後に sol_num を 1 増やしているので、写す時点の解番号は sol_num（0 始まり）。

#### 設問2 ウ

- **問われていること**：4 方向の探索後に stack_top に代入する値
- **解答例**：stack_top - 1

**解き方**：else 側の冒頭で stack_top ← stack_top＋1 としてから 4 方向の visit を呼んでいる。全方向を試し終えたら一つ前のマスに“戻る”ので、スタックポインタを元に戻す必要がある。増やした分を打ち消す stack_top − 1。

#### 設問2 エ

- **問われていること**：関数の最後で OK を代入する対象
- **解答例**：maze[x][y]

**解き方**：本文に“4 方向いずれにも進むことができないときには、現在いるマスのマス情報を OK フラグに戻し、一つ前のマスに戻る”とある。関数冒頭で maze[x][y] ← VISITED と足跡を付けたので、戻る前にそれを OK に戻す。終点に着いた場合も、他の解を探すために足跡を消す必要がある。

#### 設問3 オ

- **問われていること**：メインプログラムで“解が見つからなかった”と判定する変数
- **解答例**：sol_num

**解き方**：解を見つけるたびに sol_num が 1 増える（表1：見つけた解の総数）。visit の実行後に sol_num が 0 のままなら解はなかった。

#### 設問4(1) カ

- **問われていること**：図2 で一つ目の解が見つかった後、最初に実行される visit の引数
- **解答例**：5，3

**解き方**：図2 の障害物は (3,5)(4,5)(2,4)(4,3)(2,2)(4,1)。一つ目の解は (1,1)→(1,2)→(1,3)→(2,3)→(3,3)→(3,4)→(4,4)→(5,4)→(5,5)。(5,5) の visit は終了して呼出し元の (5,4) に戻る。(5,4) では y+1 の (5,5) を呼んだ直後なので、次は x+1（外壁）、その次の y−1 の (5,3) が OK なので visit(5, 3) が呼ばれる。

#### 設問4(2) キ

- **問われていること**：(5,3) を基点として二つ目の解が見つかるまでの“移動”の回数
- **解答例**：22

**解き方**：(5,3) から順に追う。進む：(5,2)(5,1) の 2 回、(5,1) は行き止まりで (5,2) に戻る 1 回、進む：(4,2)(3,2)(3,1)(2,1) の 4 回、(2,1) からは (1,1) が足跡ありで進めず、(3,1)(3,2)(4,2)(5,2)(5,3)(5,4)(4,4)(3,4)(3,3) と 9 回戻る。(3,3) では y+1 と x+1 は試し済み、y−1 の (3,2) へ進み、(4,2)(5,2)(5,3)(5,4)(5,5) と計 6 回進んで二つ目の解。合計 2＋1＋4＋9＋6＝22 回。

#### 設問4(2) ク

- **問われていること**：その間に (4,2) のマスが“訪問”される回数
- **解答例**：3

**解き方**：キの過程で (4,2) に移動したのは、①(5,2) から進んだとき、②(3,2) から戻ったとき、③(3,2) から再び進んだときの 3 回。“訪問”は進む・戻るどちらでも移動先になれば数えることに注意する。

### 必要な知識

- 再帰関数と深さ優先探索（バックトラック）（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）
- スタックとスタックポインタの操作（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）
- 2 次元配列による盤面・座標の表現（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）

### 採点講評のポイント

全体の正答率は平均的。設問4(1)はやや低く、一つ目の解の後の動作を理解できず終点や始点を答える誤りが多かった。(5,5) から呼出し元の (5,4) に戻り次の引数が (5,3) になることを理解してほしいとされた。設問4(2)キとクは低く、どの方向にも進めないとき呼出し元に戻る再帰の動きを再現すればよいとされた。

### この問題から学ぶこと

再帰の探索問題は、方向の試行順と“どこまで試したか”を書き留めながら、盤面を手でトレースするのが確実。進む・戻るの両方を“移動”として数えるなど、本文の定義どおりに数えることが正答のカギになる。

## 令和4年度春期 問3「パズルの解答を求めるプログラム」

- 問題冊子：[IPA 公式 PDF](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt80000009sgk-att/2022r04h_ap_pm_qs.pdf)（14〜19 ページ）
- 難易度：★★★
- 出題趣旨：数独型パズルの解法を題材に、1次元配列による盤面表現と、再帰処理による深さ優先探索（バックトラック）のプログラム及びデータ構造の特性の理解を問う。

### 状況設定

9×9の盤面を81要素の1次元配列board（添字0〜80、空白は0）で表し、左上から順に空白マスへ1〜9を入れて、行・列・3×3枠の重複チェックをしながら再帰的に探索するプログラムを作る。図5の関数solveと図6の重複チェック関数の空欄を埋める。さらに、マスごとに入れられる数字を保持するデータ構造Zを導入して重複チェックを減らす改善を検討する。

### 設問と解き方

#### 設問1 ア

- **問われていること**：solveで、対象のマスが空白でない場合の条件
- **解答例**：board[x]が0 でない

**解き方**：〔盤面の表現〕で「空白の場合は0を格納」と定義されている。図5のコメント「対象のマスが空白でない場合」は、その裏返しで board[x] が 0 でないこと。この場合は数字を入れずに次のマスへ進む。

#### 設問1 イ

- **問われていること**：次の探索で solve に渡す引数（2か所共通）
- **解答例**：x＋1

**解き方**：〔パズルを解く手順〕(1)で、マスは左から右へ、右端に達したら一行下の左端へ進む。1次元配列ではこの順番がちょうど添字の昇順になるので、次のマスは x＋1。終了判定「x が MAX_BOARD−1 より大きい」（＝81に達した）とも整合する。

#### 設問1 ウ

- **問われていること**：数字 n をマスに入れてよいかの判定条件
- **解答例**：check_ok(n, x)がtrue と等しい

**解き方**：表1で、行・列・枠の三つの重複チェックをまとめて行い、重複がなければ true を返すのは check_ok(n, x)。ルールにのっとっている（true）ときだけ board[x] ← n として次へ進む、という手順(4)の流れに合わせる。

#### 設問1 エ

- **問われていること**：再帰から戻った場合のマスの初期化に代入する値
- **解答例**：0

**解き方**：手順(4-2)「入れる数字がない場合には、マスを空白に戻して一つ前に…戻り」のとおり、再帰から戻ってきたら試した数字を取り消して空白に戻す（バックトラック）。空白は0で表すので board[x] ← 0。これを忘れると、後の重複チェックで残った数字が邪魔をする。

#### 設問2 オ

- **問われていること**：row_ok で、行の左端のマスの添字
- **解答例**：div(x, 9)*9

**解き方**：1行は9マスなので、行番号は div(x, 9)、その行の左端の添字は行番号×9。例：x＝40 なら div(40,9)＝4、4×9＝36 で、図3の [36] が5行目の左端になる。

#### 設問2 カ

- **問われていること**：行内のマスに既に n があるかの条件
- **解答例**：board[row_top＋i]がn と等しい

**解き方**：for で i を0〜8まで回し、左端から右へ1つずつ見る。行内では添字が1ずつ増えるので board[row_top＋i]。それが n と等しければ重複なので false を返す。図6の frame_ok の if 文（board[...]がnと等しい）と同じ書き方にそろえる。

#### 設問2 キ

- **問われていること**：column_ok で、列の上端のマスの添字
- **解答例**：mod(x, 9)

**解き方**：列番号は x を9で割った余り mod(x, 9) で、上端（1行目）のマスの添字は列番号そのもの。例：x＝40 なら mod(40,9)＝4 で、上端は [4]。

#### 設問2 ク

- **問われていること**：列内のマスに既に n があるかの条件
- **解答例**：board[column_top＋9*i]がn と等しい

**解き方**：列内で1つ下のマスは添字が9増える（図3で [4]→[13]→[22]…）。よって上端から i 番目は column_top＋9*i。frame_ok の「frame_top＋9*i＋j」も同じ考え方で、行方向は9刻み・列方向は1刻みと覚える。

#### 設問2 ケ

- **問われていること**：frame_top ← x − ケ − mod(x, 3) で、枠の左上端を求めるために引く値
- **解答例**：mod(div(x, 9)*9, 27)

**解き方**：x から mod(x, 3) を引くと、同じ行のうち枠の左端の列にそろう。あとは枠の中で何行目か（0〜2行目）を求め、その行数×9を引けば枠の上端の行に戻る。枠内の行位置は mod(div(x, 9), 3)、引くべき値は mod(div(x, 9), 3)×9 ＝ mod(div(x, 9)*9, 27)。検算：x＝40 → div(40,9)*9＝36、mod(36,27)＝9、mod(40,3)＝1 なので frame_top＝40−9−1＝30。図3で [30] は4行目・4列目＝中央の枠の左上端で正しい。採点講評どおり、具体的な x をいくつか代入して確かめるのが確実。

#### 設問3 処理A

- **問われていること**：数字を入れる前に行う処理A（“データ構造Z”を含めて20字以内）
- **解答例**：データ構造Z を退避する

**解き方**：(3-1)では数字を入れた後に Z の更新処理（その行・列・枠の該当数字を0にする）を行う。しかし後で行き詰まって戻るとき、Z を元の状態に戻す必要がある。0にした要素を一つ一つ1に戻すのは、他のマスの影響で元から0だったものと区別できず難しい。そこで数字を入れる前に Z をまるごと保存（退避）しておく。

#### 設問3 処理B

- **問われていること**：マスを空白に戻した後に行う処理B（“データ構造Z”を含めて20字以内）
- **解答例**：退避したデータ構造Z を取り出す

**解き方**：(3-2)で一つ前のマスに戻るとき、盤面だけでなく Z もそのマスに数字を入れる前の状態に戻さないと、以降の探索で入れられる数字の判定が狂う。処理Aで退避しておいた Z を取り出して元に戻す。Z は大域変数なので、再帰の各段で退避・復元する“スタック”的な扱いになる、と考えるとよい。

### 必要な知識

- 再帰と深さ優先探索・バックトラック（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）
- 2次元の盤面を1次元配列で表すときの添字計算（div・mod）（[アルゴリズムとプログラミング](../../01_テクノロジ系/02_アルゴリズムとプログラミング.md)）

全体の正答率は平均的。設問2のケは正答率が低く、添字x・枠の先頭・mod(x, 3)の組合せを列挙して剰余と商の性質から着実に求めてほしいとされた。設問3も正答率が低く、処理Aで大域変数Zを退避し、処理Bで取り出して数字を入れる前の状態に戻すことを理解してほしいとされた。

### この問題から学ぶこと

1次元配列で盤面を扱う問題は、具体的な添字（例：x＝40）を代入して検算するのが最強の武器。再帰による探索では“戻るときに状態を元に戻す”処理が必ず必要になることを覚えておく。
