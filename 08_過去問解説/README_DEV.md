# 過去問解説 データ仕様

IPA が公表している応用情報技術者試験の過去問題を、出典を明記して教材化したものです。

> IPA「試験制度に関するよくある質問」より：教育目的など試験制度の意義に反しない限り、公表されている過去問題を問題集やテキストに使用する際、許諾および使用料は不要。出典（年度・期・試験区分・時間区分・問番号）を明記し、一部を改変した場合はその旨も明記する。

## フォルダ構成

```
08_過去問解説/
  科目A/
    data/<id>.json     … 1回分（80問）の正本データ（このファイルだけを編集する）
    img/<id>_qNN.png   … 文章や表で表せない図の切り出し画像
    <id>.md            … data から自動生成する解説集（手で編集しない）
  科目B/
    問NN_<分野>.md      … 分野別の過去問分析と解き方
tools/
  build_past.py        … data/*.json → Markdown 解説集とクイズ用 JS を生成
  validate_past.py     … data/*.json の形式・正解・画像の存在を検査
```

`<id>` は IPA のファイル名に合わせる（例：`2025r07a` = 令和7年度秋期、`2025r07h` = 令和7年度春期、`2020r02o` = 令和2年度10月）。

## data/<id>.json の形式

```json
{
  "id": "2025r07a",
  "label": "令和7年度秋期",
  "questions": [
    {
      "no": 4,
      "field": "tech",
      "category": "基礎理論",
      "q": "誤り検出方式である CRC に関する記述として，適切なものはどれか。",
      "choices": ["検査用のデータは，…", "受信側では，…", "送信側では，…", "送信側と受信側では，…"],
      "answer": 2,
      "figures": [],
      "calc": false,
      "keywords": ["CRC", "生成多項式"],
      "explanation": "…",
      "modified": ""
    }
  ]
}
```

| キー | 内容 |
|---|---|
| `no` | 問番号（1〜80） |
| `field` | `tech` / `mgmt` / `strat`（IPA 解答例の分野 T/M/S と一致させる） |
| `category` | シラバス Ver.7.2 の **中分類名**（下の23個のどれか） |
| `q` | 問題文。Markdown 可（表は GFM の表、プログラム・擬似言語はコードブロック）。原文の句読点「，」「。」はそのまま |
| `choices` | 選択肢 ア〜エ の本文（記号「ア」などは付けない）。選択肢が図そのものの場合は `"（図のア）"` のように書き、`figures` に図を入れる |
| `answer` | 正解の添字（ア=0, イ=1, ウ=2, エ=3）。IPA 解答例と一致させる |
| `figures` | `img/<id>_qNN.png` 形式の相対パスの配列（`科目A/` から見たパス）。表や式で書き直せるものは画像にしない |
| `calc` | 計算が必要な問題なら `true` |
| `keywords` | 検索用キーワード 1〜5個 |
| `explanation` | **オリジナルの解説**（Markdown）。下の「解説の書き方」に従う |
| `modified` | 原文から改変した点（例：`"図を表に書き換え"`）。改変なしなら空文字 |

### 中分類（23個）

テクノロジ系：基礎理論 / アルゴリズムとプログラミング / コンピュータ構成要素 / システム構成要素 / ソフトウェア / ハードウェア / ユーザーインタフェース / 情報メディア / データベース / ネットワーク / セキュリティ / システム開発技術 / ソフトウェア開発管理技術
マネジメント系：プロジェクトマネジメント / サービスマネジメント / システム監査
ストラテジ系：システム戦略 / システム企画 / 経営戦略マネジメント / 技術戦略マネジメント / ビジネスインダストリ / 企業活動 / 法務

## 書き起こしのルール

- 問題文・選択肢は **原文どおり** に書き起こす（誤字を勝手に直さない。全角英数字は半角にしてよい）。
- 表は GFM の表に、数式はテキスト（`x^2`、`log2 n`、分数は `a / b`）に、擬似言語・プログラムはコードブロックにする。こうして書き直したら `modified` に記録する。
- 論理回路・グラフ・ネットワーク図・UML など文章で表せない図は、図の切り出しツール（PDF をページ画像にして該当範囲を切り出す）で `img/` に置く。

## 解説の書き方

1. **結論**：正解とその根拠を1〜3文で。
2. **計算問題** は途中式を必ず書く（公式 → 代入 → 答え）。
3. **各選択肢**：誤りの選択肢について、何の説明なのか・どこが誤りなのかを1行ずつ（例：「ア：パリティチェックの説明。CRC の検査データは1ビットではない」）。
4. **💡 ポイント**：覚えるべき知識・類題での問われ方を1〜2行。
5. 関連する解説資料があればリンク（例：`[基礎理論](../../01_テクノロジ系/01_基礎理論.md)`。`科目A/<id>.md` から見た相対パス）。

解説は **自分の言葉で書く**（市販書籍や解説サイトの文章を写さない）。正解が IPA の解答例と食い違う解説を書いてはいけない。

# 科目B（旧午後）過去問分析 データ仕様

科目B の問題冊子は分量が多く図も多いため、**問題文は書き起こさず**、IPA の PDF を見ながら使う「解き方ガイド」として作ります。

- 対象：令和4年度春期〜令和7年度秋期の8回 × 11問
- 正本データ：`科目B/data/<id>.json`（1回分11問）。`tools/build_past.py` が分野別の `科目B/問NN_<分野>.md` を生成する。

```json
{
  "id": "2025r07a",
  "label": "令和7年度秋期",
  "pdf": "https://www.ipa.go.jp/shiken/mondai-kaiotu/…/2025r07a_ap_pm_qs.pdf",
  "problems": [
    {
      "no": 1,
      "field": "情報セキュリティ",
      "title": "サプライチェーン攻撃への対策",
      "pages": "2〜7",
      "theme": "IPA の出題趣旨の要約（1〜2文）",
      "situation": "問題の状況設定の要約（どんな会社・システムで、何が起きたか。3〜5文）",
      "questions": [
        {
          "label": "設問3(2)",
          "ask": "何を問われているか（要約）",
          "answer": "IPA の解答例（原文どおり）",
          "howto": "解き方：本文のどこに着目し、どの知識をどう使えば解答例にたどり着くか（オリジナル）"
        }
      ],
      "knowledge": ["この問題を解くのに必要な知識（関連資料へのリンクつき）"],
      "comment": "IPA 採点講評の要点（要約）",
      "difficulty": 2,
      "lessons": "この問題から学ぶべきこと・次に同じテーマが出たときの心構え（2〜3文）"
    }
  ]
}
```

| キー | 内容 |
|---|---|
| `field` | 情報セキュリティ / 経営戦略 / プログラミング / システムアーキテクチャ / ネットワーク / データベース / 組込みシステム開発 / 情報システム開発 / プロジェクトマネジメント / サービスマネジメント / システム監査 |
| `pages` | 問題冊子の印刷ページ番号（ページ下部の「− 5 −」の数字）の範囲 |
| `answer` | IPA 解答例を原文どおりに（出典は自動で付ける） |
| `howto` | **オリジナル**の解き方解説。問題文を長く引用しない。「本文〔〇〇〕の△△という記述から」のように根拠の場所を示す |
| `difficulty` | 1（易）〜3（難）。採点講評の正答率の言及や設問内容から判断 |
