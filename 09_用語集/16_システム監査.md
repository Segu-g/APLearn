<a id="まぎらわしい用語"></a>

## まぎらわしい用語

| 用語 | 用語 | 違い |
|---|---|---|
| **システム監査基準** | **システム管理基準** | 監査基準は監査人が守る行為規範（監査のやり方）。管理基準は組織が守る管理の実践規範で、監査では判断の尺度になる。 |
| **保証型監査（保証を目的としたシステム監査）** | **助言型監査（助言を目的としたシステム監査）** | 保証型は対象が適切であることを意見として表明する。助言型は問題点を指摘し改善の助言を行う。組み合わせて実施してもよい。 |
| **内部監査** | **外部監査** | 内部監査は組織内の独立した監査部門が経営者のために行う。外部監査は監査法人など外部の第三者が利害関係者のために行う。 |
| **予備調査** | **本調査** | 予備調査は資料やヒアリングで監査対象の実態を概括的に把握する。本調査は監査手続を実施して監査証拠を入手する。 |
| **監査要点** | **監査手続** | 監査要点は確かめるべきポイント（何を）。監査手続はそれを確かめて証拠を入手する具体的な方法（どうやって）。 |
| **ウォークスルー法** | **インタビュー法（質問書・調査票）** | ウォークスルー法はデータの生成から活用までの流れとコントロールを追跡する。インタビュー法は関係者に口頭で質問して回答を得る。 |
| **テストデータ法** | **並行シミュレーション法** | テストデータ法は監査人がデータを用意して本番プログラムで処理する。並行シミュレーション法は監査人がプログラムを用意して本番と同じデータを処理し結果を比べる。 |
| **監査証拠** | **監査調書** | 監査証拠は結論を裏付ける事実や資料。監査調書は実施した手続・入手した証拠・判断の過程を監査人が記録した文書。 |
| **監査調書** | **監査報告書** | 監査調書は監査人の作業記録で結論の根拠。監査報告書は結論・指摘事項・改善提案をまとめて監査依頼者に提出する。 |
| **改善提案** | **改善計画** | 改善提案は監査人が示す改善の勧告。改善計画は被監査部門が作る実行計画で、監査人が作成してはならない。 |
| **情報セキュリティ監査基準** | **情報セキュリティ管理基準** | 監査基準は情報セキュリティ監査人の行為規範。管理基準は監査の判断の尺度（管理策の基準）。 |
| **COSOフレームワーク** | **内部統制の基本的要素** | COSOは3目的・5構成要素。J-SOXの基本的要素はそれに「ITへの対応」を加えた6要素（目的も資産の保全を加え4つ）。 |
| **ITに係る全般統制** | **ITに係る業務処理統制** | 全般統制は開発・運用・アクセス管理など複数のシステムを支える基盤の統制。業務処理統制は個々の業務システム内の入力チェックや照合などの統制。 |
| **CSA（統制自己評価）** | **内部監査** | CSAは業務部門が自らリスクとコントロールを評価する。内部監査は独立した監査部門が評価する。 |
