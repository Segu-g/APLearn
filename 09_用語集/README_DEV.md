# 用語集 データ仕様・編集ルール

用語集は `data/NN_<中分類>.json`（シラバス Ver.7.2 の中分類ごと、全23ファイル）を **唯一の元データ** として、次を自動生成します。手で編集するのは `data/*.json` だけです。

| 生成物 | 生成元 |
|---|---|
| `09_用語集/NN_<中分類>.md`、`09_用語集/README.md` | `tools/build_terms.py` |
| `06_インタラクティブ教材/data/terms.js`（用語ドリル用） | 同上 |

```bash
python3 09_用語集/tools/validate_terms.py   # 形式チェック
python3 09_用語集/tools/build_terms.py      # Markdown と terms.js を作り直す
```

初版は各章末の「📋 シラバス用語チェックリスト」から `tools/extract_from_chapters.py` で抜き出し、その後、過去問との照合・重要度付け・説明の手直しをしています。

## ファイルの形式

```json
{
  "no": 10,
  "category": "ネットワーク",
  "field": "tech",
  "pairs": [
    { "a": "TCP", "b": "UDP", "diff": "TCPはコネクション型で再送・順序制御あり（信頼性重視）。UDPはコネクションレスで軽く速い（音声・動画、DNS問合せ）。" }
  ],
  "terms": [
    {
      "term": "サブネットマスク",
      "en": "subnet mask",
      "desc": "IPアドレスのうちネットワーク部を示すビット列。ネットワーク部を1、ホスト部を0で表す",
      "point": "/26 なら 255.255.255.192、ホストに使えるのは 2^6−2＝62台。AND演算でネットワークアドレスを求める計算が頻出",
      "imp": 3,
      "past": ["2024r06h-31", "2022r04a-33"],
      "sub": "通信プロトコル",
      "src": "01_テクノロジ系/07_ネットワーク.md#..."
    }
  ]
}
```

| キー | 必須 | 内容 |
|---|---|---|
| `term` | ○ | 用語の表記。略語は略語で書き、正式名称は `en` に |
| `en` | | 略語の正式名称（英語）や英語表記。不要なら省略 |
| `desc` | ○ | **1行の定義**（目安70字以内）。「〜すること」「〜する仕組み」など、それだけで意味が分かる文 |
| `point` | ★★★は○ | 試験での問われ方・見分け方・覚え方・具体的な数値例（目安120字以内）。定義の言い換えではなく、得点につながる一言 |
| `imp` | ○ | 重要度 1〜3（下記） |
| `past` | | その用語が **実際に問われた** 科目A過去問（`<回のid>-<問番号2桁>`、最大4件。表示は自動で新しい順） |
| `sub` | ○ | 小分類（Markdown の見出しになる） |
| `src` | | 詳しい解説がある章へのリンク（リポジトリのルートからの相対パス＋アンカー）。章に説明が無い用語は省略 |
| `pairs` | | まぎらわしい用語の組（各中分類 5〜15組）。`diff` に違いを1〜2文で |

### 重要度（imp）の目安

| imp | 表示 | 基準 | 割合の目安 |
|---|---|---|---|
| 3 | ★★★ | 過去問で繰り返し問われた／科目Bでも前提になる基本語 | 1〜2割 |
| 2 | ★★ | 過去問で1回問われた／定番の知識で出題されやすい | 2〜3割 |
| 1 | ★ | シラバスに載っているが出題実績の少ない語 | 残り |

## 編集ルール

- 内容は既存の解説（`01_テクノロジ系/` など）と矛盾しないこと。法令は 2026年10月時点。
- `past` は問題文・選択肢・解説を見て、その用語の知識が解答に必要だった問だけを入れる（文中にたまたま出ただけの問は入れない）。
- 「A・B・C」のようにシラバスの複数の語を1行にまとめた項目は、それぞれが独立して問われうる語なら分割してよい。
- 過去問で問われたのにシラバス抜粋に無い用語は追加してよい（`src` は省略可）。
