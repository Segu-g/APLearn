<a id="まぎらわしい用語"></a>

## まぎらわしい用語

| 用語 | 用語 | 違い |
|---|---|---|
| **プリエンプティブ方式** | **ノンプリエンプティブ方式** | プリエンプティブは OS が実行中のタスクを中断して切り替えられる（横取りあり）。ノンプリエンプティブは実行中のタスクが自ら CPU を手放すまで切り替わらない。 |
| **実行可能状態** | **待ち状態** | 実行可能状態は CPU さえあればすぐ動ける状態、待ち状態は入出力完了などを待っていて CPU があっても動けない状態。横取りされたタスクは実行可能状態へ、入出力要求を出したタスクは待ち状態へ移る。 |
| **プロセス** | **スレッド（軽量プロセス）** | プロセスは OS が資源（メモリ空間）を割り当てる単位。スレッドはプロセス内の実行の流れで、同じプロセスのメモリを共有するため生成・切替えが軽い。 |
| **処理時間順方式（SJF）** | **ラウンドロビン** | 処理時間順は短いジョブ優先で平均ターンアラウンドタイム最小だが、長いジョブが待たされ続ける（スタベーション）。ラウンドロビンは一定時間ずつ順番に回すので全タスクに必ず順番が来る。 |
| **ファーストフィット** | **ベストフィット** | ファーストフィットは先頭から探して最初に入る領域、ベストフィットは入る領域のうち最小の領域を割り当てる。最大の領域を選ぶのはワーストフィット。 |
| **LRU** | **FIFO** | LRU は最後に参照されてから最も時間が経ったページを、FIFO は最も古くに読み込まれたページを追い出す。FIFO は再参照されても順番が変わらない。 |
| **ページング方式** | **セグメント方式** | ページングは固定長のページ単位で管理し外部断片化が起きない。セグメント方式は論理的なまとまり（可変長）単位で、保護・共有はしやすいが外部断片化が起こる。 |
| **コンパクション** | **ガーベジコレクション** | コンパクションは使用中の領域を移動して細切れの空き領域を1つにまとめる。ガーベジコレクションは使われなくなった領域を回収して再利用可能にする。 |
| **再入可能（リエントラント）** | **再使用可能** | 再入可能は複数タスクから同時に呼ばれても正しく動く（データをタスクごとに持つ）。再使用可能は再ロードせずに繰り返し使えるが、同時実行はできない。 |
| **スタック領域** | **ヒープ領域** | スタック領域は戻り番地や局所変数を後入れ先出しで積む（解放の順序が決まっている）。ヒープ領域は実行中に任意の順序で動的に確保・解放する。 |
| **差分バックアップ** | **増分バックアップ** | 差分は前回のフル以降の変更分で、復元はフル＋最新の差分1つ。増分は前回のバックアップ以降の変更分で、取得は速いが復元にはフル＋すべての増分が必要。 |
| **コンパイラ** | **インタプリタ** | コンパイラはソース全体を事前に機械語へ翻訳してから実行（実行が速い）。インタプリタは1命令ずつ解釈しながら実行（すぐ動かせるが遅い）。 |
| **GPL** | **LGPL** | GPL は結合した派生物全体にソース公開義務が及ぶ。LGPL はライブラリとしてリンクして使うだけなら、利用側プログラムのソースを公開しなくてよい。 |
| **デュアルシステム** | **デュプレックスシステム** | デュアルは2系統で同じ処理を同時に行い結果を照合する。デュプレックスは現用系と待機系を持ち、故障時に待機系へ切り替える。 |
| **Git** | **Subversion** | Git は各開発者が全履歴を含むリポジトリの複製を持つ分散型。Subversion は中央のリポジトリだけで履歴を管理する集中型。 |

## 一問一答（★★★）

説明を読んで用語を答えてください。クリックすると答えが開きます。

<details><summary>Q1. 決められた時間（デッドライン）内に処理を完了させることを保証する OS。組込み機器で使う</summary>

**リアルタイム OS**（Real-Time Operating System（RTOS））
</details>

<details><summary>Q2. 実行中の処理を中断して緊急の処理を先に行うしくみ</summary>

**割込み**（interrupt）
</details>

<details><summary>Q3. 入出力待ちの間に別プログラムへ CPU を回し、CPU 遊休を減らす方式</summary>

**多重（マルチ）プログラミング**（multiprogramming）
</details>

<details><summary>Q4. 実行中のプログラム。OS が資源を割り当てる単位</summary>

**プロセス**（process）
</details>

<details><summary>Q5. プロセス内の処理の流れの単位。同じプロセス内のスレッドはメモリ空間を共有する</summary>

**スレッド（軽量プロセス）**（thread）
</details>

<details><summary>Q6. CPU が割り当てられればすぐ実行できる状態。実行待ちの列に並んでいる（レディ）</summary>

**実行可能状態**
</details>

<details><summary>Q7. CPU を割り当てられて実行中の状態（ラン）。シングルコアでは同時に1つだけ</summary>

**実行状態**
</details>

<details><summary>Q8. 入出力の完了などを待っていて、CPU があっても実行できない状態（ウェイト）</summary>

**待ち状態**
</details>

<details><summary>Q9. 実行中のタスクを中断させ、CPU を別のタスクに割り当てられる（横取りできる）方式</summary>

**プリエンプティブ方式**（preemptive）
</details>

<details><summary>Q10. 実行中のタスクが自ら CPU を手放すまで、OS がタスクを切り替えない方式</summary>

**ノンプリエンプティブ方式**（non-preemptive）
</details>

<details><summary>Q11. 処理時間の短いジョブ（タスク）から順に実行するスケジューリング方式。最短時間順ともいう</summary>

**処理時間順方式（SJF）**（Shortest Job First）
</details>

<details><summary>Q12. 一定時間（タイムクウォンタム）ずつ順番に CPU を割り当て、終わらなければ待ち行列の末尾に戻す方式</summary>

**ラウンドロビン**（round robin）
</details>

<details><summary>Q13. ジョブを投入（到着）してから処理結果が得られるまでの時間。終了時刻−到着時刻</summary>

**ターンアラウンドタイム**（turnaround time）
</details>

<details><summary>Q14. 共有資源を同時に1タスクだけが使うようにする制御</summary>

**排他制御**（mutual exclusion）
</details>

<details><summary>Q15. 排他制御や同期のために使うカウンタと、それを増減する P 操作・V 操作からなるしくみ</summary>

**セマフォ**（semaphore）
</details>

<details><summary>Q16. 複数のタスクが互いに相手の確保した資源の解放を待ち合い、どれも先に進めなくなる状態</summary>

**デッドロック**（deadlock）
</details>

<details><summary>Q17. 要求量以上の空き領域のうち、最も小さい（余りが最小の）領域を割り当てる方式</summary>

**ベストフィット**（best fit）
</details>

<details><summary>Q18. 割当てと解放の繰返しで空き領域が細切れになり、合計は足りても連続領域を確保できなくなる現象（断片化）</summary>

**フラグメンテーション**（fragmentation）
</details>

<details><summary>Q19. プログラムが使わなくなったヒープ領域を回収し、再び利用できるようにする機能</summary>

**ガーベジコレクション**（garbage collection）
</details>

<details><summary>Q20. 補助記憶を利用して、主記憶より大きな仮想アドレス空間をプログラムに提供する OS の機能</summary>

**仮想記憶管理**（virtual memory）
</details>

<details><summary>Q21. 仮想アドレス空間と主記憶を固定長のページに分けて管理する仮想記憶方式</summary>

**ページング方式**（paging）
</details>

<details><summary>Q22. 参照したページが主記憶上にないときに発生する割込み。OS が補助記憶からページを読み込む</summary>

**ページフォールト**（page fault）
</details>

<details><summary>Q23. 主記憶上のページを補助記憶へ書き出して、主記憶の枠を空けること</summary>

**ページアウト**
</details>

<details><summary>Q24. ページイン・アウトが頻発し処理がほとんど進まなくなる現象</summary>

**スラッシング**（thrashing）
</details>

<details><summary>Q25. 最後に参照されてから最も長い時間が経過したページ（ブロック）を追い出す置換え方式</summary>

**LRU**（Least Recently Used）
</details>

<details><summary>Q26. 最も古くに読み込まれたページ（ブロック）を追い出す置換え方式</summary>

**FIFO**（First In First Out）
</details>

<details><summary>Q27. ソースプログラム全体を機械語の目的プログラムにまとめて翻訳する言語処理プログラム</summary>

**コンパイラ**（compiler）
</details>

<details><summary>Q28. 複数のタスクから同時に呼び出されても、正しく並行して実行できるプログラムの性質</summary>

</details>

<details><summary>Q29. アプリケーションが OS・ライブラリ・他のサービスの機能を呼び出すための、ソースコードレベルの取り決め</summary>

**API**（Application Programming Interface）
