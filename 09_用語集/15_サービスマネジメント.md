<a id="まぎらわしい用語"></a>

## まぎらわしい用語

| 用語 | 用語 | 違い |
|---|---|---|
| **インシデント管理** | **問題管理** | インシデント管理は回避策などでサービスをできるだけ早く復旧させる。問題管理は根本原因を特定し、再発を防ぐ恒久的な解決策を検討する。 |
| **回避策** | **解決策** | 回避策は根本原因を残したまま影響を減らす一時的な方法。解決策は根本原因を取り除く恒久的な方法。 |
| **変更管理** | **リリース及び展開管理** | 変更管理は変更を評価・承認する（やってよいか決める）。リリース及び展開管理は承認された変更を稼働環境へ実際に展開する。 |
| **標準変更** | **緊急変更** | 標準変更は低リスクで手順が確立した事前承認済みの変更。緊急変更は急を要する変更で、ECABで迅速に判断する。 |
| **機能的エスカレーション** | **階層的エスカレーション** | 機能的は専門部署（二次・三次サポート）への技術的な引継ぎ（横）。階層的は上位管理者への報告と判断の要請（縦）。 |
| **SLA** | **SLO** | SLAは顧客と合意した文書全体。SLOはその中に盛り込む個々の目標値（例：稼働率99.9%）。 |
| **MTBF** | **MTTR** | MTBFは故障と故障の間の平均稼働時間（長いほど信頼性が高い）。MTTRは故障1回あたりの平均修復時間（短いほど保守性が高い）。 |
| **MTTR** | **MTRS** | MTTRは機器の修理にかかる平均時間。MTRSはサービス中断から利用者が再び使えるまでの平均時間で、検知・連絡・確認も含む。 |
| **RTO（目標復旧時間）** | **RPO（目標復旧時点）** | RTOは中断から何時間で復旧させるか。RPOはどの時点のデータまで戻すかで、バックアップの取得間隔を決める。 |
| **ホットスタンバイ** | **コールドスタンバイ** | ホットは予備系も起動・同期済みで数秒〜数分で切替え（高コスト）。コールドは予備機を停止させておき起動・設定から行う（低コスト・数時間〜数日）。 |
| **差分バックアップ** | **増分バックアップ** | 差分は直前のフル以降の変更分で、復元はフル＋最新の差分1つ。増分は前回のバックアップ以降の分で、復元はフル＋全増分を順に適用。 |
| **是正処置** | **予防処置** | 是正処置は発生した不適合の原因を除去して再発を防ぐ。予防処置はまだ起きていない問題の原因を除いて発生を防ぐ。 |
| **KGI** | **KPI** | KGIは最終目標の達成度を測る指標。KPIはそこに至るプロセスの進み具合を測る中間指標。 |
| **FTA（故障の木解析）** | **FMEA（故障モード影響解析）** | FTAは望ましくない事象から原因へさかのぼるトップダウン型。FMEAは部品の故障モードから影響へ進むボトムアップ型。 |
| **運用テスト** | **受入れテスト** | 運用テストは運用部門が実際の手順・体制で運用できるか確認する。受入れテストは利用者が業務要件どおりか確認して受け入れる。 |
