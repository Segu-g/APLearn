| ★★ | **進展的モデル** [📖](../01_テクノロジ系/12_ソフトウェア開発管理技術.md#11-開発モデルの全体像-)<br><sub>evolutionary model</sub> | 要件の一部から開発を始め、反復のたびに要件を明確化・追加しながらシステムを進化させるモデル<br>💡 エボリューション＝進化。完成図そのものが育つ。「最初に全体の要件を確定」とあれば段階的モデルの方 |  |
| ★ | **ソフトウェアプロダクトライン** [📖](../01_テクノロジ系/12_ソフトウェア開発管理技術.md#11-開発モデルの全体像-)<br><sub>software product line</sub> | 似た製品群の共通部分をコア資産として用意し、製品ごとの違い（可変性）だけを追加して効率よく開発する方式<br>💡 「計画的・戦略的な再利用」がキーワード。機種違いの家電など組込み分野で多い |  |

## まぎらわしい用語

| 用語 | 用語 | 違い |
|---|---|---|
| **段階的モデル** | **進展的モデル** | 段階的モデルは最初に全体の要件を確定し、分割して順に作る。進展的モデルは反復のたびに要件を明確化・追加してシステムを育てる。 |
| **XP（エクストリームプログラミング）** | **スクラム** | XPはTDD・ペアプログラミングなどプログラミングの実践が中心。スクラムは役割・イベント・作成物を定めたチーム運営（管理）の枠組み。 |
| **ペアプログラミング** | **モブプログラミング** | ペアプログラミングは2人で1つのコードを書く。モブプログラミングはチーム全員が1つの画面で同じコードを書く。 |
| **プロダクトオーナー** | **スクラムマスター** | プロダクトオーナーはプロダクトバックログの優先順位を決め価値を最大化する。スクラムマスターはスクラムの理解と実践を支援し妨げを取り除く。 |
| **スプリントレビュー** | **スプリントレトロスペクティブ** | レビューは成果物（インクリメント）をステークホルダに見せて進捗を話し合う。レトロスペクティブはチームの進め方を振り返る。順序はレビュー→レトロ。 |
| **プロダクトバックログ** | **スプリントバックログ** | プロダクトバックログはプロダクト全体の要求一覧でPOが管理する。スプリントバックログはそのスプリントで取り組む項目と作業計画で開発者が管理する。 |
| **バーンダウンチャート** | **バリューストリームマップ** | バーンダウンチャートは残作業量の推移を表すグラフ。バリューストリームマップはプロセスと所要時間を可視化してムダやボトルネックを探す図。 |
| **継続的デリバリー（CD）** | **継続的デプロイ** | 継続的デリバリーはリリース可能な状態まで自動化し、本番反映は人が判断する。継続的デプロイはテスト合格後に本番反映まで自動で行う。 |
| **ローコード開発** | **ノーコード開発** | ローコード開発はGUIで部品を組み合わせ、一部の処理だけコードを書く。ノーコード開発はコードをまったく書かない。 |
| **ネイティブアプリケーションソフトウェア** | **PWA（プログレッシブウェブアプリ）** | ネイティブアプリはOSごとのSDKで作りストアから配布する。PWAはWebアプリのままサービスワーカーでオフライン動作やプッシュ通知を実現する。 |
| **ブラックボックス部品** | **ホワイトボックス部品** | ブラックボックス部品は内部を見せずインタフェースだけで使う。ホワイトボックス部品はソースが公開され中身を修正して使う。 |
| **JIS X 33020** | **CMMI** | JIS X 33020はプロセスごとの能力を0〜5の6段階で測る。CMMIは組織の成熟度を1〜5の5段階で表す。 |
| **専用実施権** | **通常実施権** | 専用実施権は登録が必要な独占的権利で、その範囲では特許権者も実施できない。通常実施権は非独占で複数に許諾でき登録不要。 |
| **ライセンサー** | **ライセンシー** | ライセンサーは使用を許諾する側（権利者）。ライセンシーは許諾を受けて使う側。 |
| **CPRM** | **AACS** | CPRMは録画用DVDやSDカードなど記録メディア向け。AACSはBlu-ray Discなどで使われる。 |

<details><summary>Q4. 役割（プロダクトオーナー等）・イベント（スプリント等）・作成物（バックログ等）とルールから成るチーム開発の枠組み</summary>

**スクラム**（Scrum）
</details>

<details><summary>Q5. トヨタ生産方式の考え方をソフトウェア開発に応用し、ムダの排除など7つの原則で進めるアジャイル手法</summary>

**リーンソフトウェア開発**（Lean Software Development）
</details>

<details><summary>Q6. プログラムを書く前にテストコードを書き、それに合格するコードを作ってからリファクタリングする開発手法</summary>

**テスト駆動開発（TDD）**（Test Driven Development）
</details>

<details><summary>Q7. 2人のプログラマが1台のPCで、1人が書きもう1人がその場でレビュー・相談しながら1つのプログラムを開発する実践</summary>

**ペアプログラミング**（pair programming）
</details>

<details><summary>Q8. プロダクトの価値を最大化する責任者。プロダクトバックログを管理し、項目の優先順位を決める</summary>

**プロダクトオーナー**（Product Owner）
</details>

<details><summary>Q9. スクラムの理論と実践を全員が理解できるよう支援し、チームの妨げを取り除くサーバントリーダー</summary>

**スクラムマスター**（Scrum Master）
</details>

<details><summary>Q10. 1か月以内の固定期間で区切った開発の反復単位。他のスクラムイベントはすべてこの中で行う</summary>

**スプリント**（Sprint）
</details>

<details><summary>Q11. スプリントの成果（インクリメント）をステークホルダに示し、プロダクトゴールへの進捗を話し合うイベント</summary>

**スプリントレビュー**（Sprint Review）
</details>

<details><summary>Q12. スプリントの最後に、チームの進め方（人・プロセス・ツール）を振り返り改善策を決めるイベント</summary>

**スプリントレトロスペクティブ**（Sprint Retrospective）
</details>

<details><summary>Q13. 縦軸に残作業量、横軸に時間をとり、残作業の減り方を理想線と比べて進捗を見るグラフ</summary>

**バーンダウンチャート**（burndown chart）
</details>

<details><summary>Q14. 1スプリントでチームが完了させたストーリーポイントの合計。チームの生産量を相対的に表す尺度</summary>

**ベロシティ**（velocity）
</details>

<details><summary>Q15. ふりかえりの手法。続けること（Keep）、問題点（Problem）、次に試すこと（Try）を書き出す</summary>

**KPT（Keep，Problem，Try）**（Keep, Problem, Try）
</details>

<details><summary>Q16. 開発（Dev）と運用（Ops）が協力し、自動化と継続的な改善で素早く安定したリリースを続ける考え方</summary>

**DevOps**（Development and Operations）
</details>

<details><summary>Q17. 開発者の変更を頻繁にメインラインへ統合し、そのたびに自動でビルド・テストする実践</summary>

**継続的インテグレーション（CI）**（Continuous Integration）
</details>

<details><summary>Q18. IPAが日本の取引慣行に合わせて作った、ソフトウェア開発・取引の共通の物差しとなるプロセスの枠組み（共通フレーム2013）</summary>

**SLCP-JCF（共通フレーム）**（SLCP-Japan Common Frame）
</details>

<details><summary>Q19. 法人の発意で従業員が職務上作成したプログラムは、契約や就業規則に別段の定めがなければ法人が著作者になる</summary>

**職務著作**
</details>

<details><summary>Q20. 発明を独占的に実施できる権利。特許庁への出願・審査を経た登録で発生し、存続期間は原則出願から20年</summary>

**特許権**（patent right）
</details>

<details><summary>Q21. ソフトウェアに含まれるコンポーネント（OSSなど）の名前・バージョン・ライセンス・依存関係の一覧（ソフトウェア部品表）</summary>

**SBOM**（Software Bill of Materials）
</details>
