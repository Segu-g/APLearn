<a id="まぎらわしい用語"></a>

## まぎらわしい用語

| 用語 | 用語 | 違い |
|---|---|---|
| **ラジオボタン** | **チェックボックス** | ラジオボタンは選択肢から1つだけ選ぶ。チェックボックスは複数選択でき、単独の ON/OFF にも使う。 |
| **アフォーダンス** | **シグニファイア** | アフォーダンスはモノと人の関係として可能な行為そのもの。シグニファイアはその行為の仕方を利用者に伝える目印。 |
| **アクセシビリティ** | **ユニバーサルデザインの 7 原則** | アクセシビリティは障害のある人などが利用できるよう障壁をなくすこと。ユニバーサルデザインは最初からすべての人が使いやすいように作る考え方。 |
| **ヒューリスティック評価** | **思考発話法** | ヒューリスティック評価は専門家が経験則に照らして行う。思考発話法は利用者に考えを声に出しながら操作してもらう。 |
| **思考発話法** | **回顧法** | 思考発話法は操作しながら考えを話してもらう。回顧法は操作が終わった後で録画を見ながら考えを聞く。 |
| **認知的ウォークスルー** | **ユーザビリティテスト** | 認知的ウォークスルーは専門家が初心者になりきって手順をたどる。ユーザビリティテストは実際の利用者に課題を実行してもらい観察する。 |
| **オブジェクト指向 UI（OOUI）** | **タスク指向 UI** | OOUI は対象（名詞）を先に選び操作（動詞）を後で選ぶ。タスク指向 UI はやりたいこと（動詞）を先に選び対象を後で指定する。 |
| **スワイプ** | **フリック** | スワイプは触れたまま指を滑らせる操作。フリックは指を素早くはじく操作。 |
| **リミットチェック** | **フォーマットチェック** | リミットチェックは値が上限・下限の範囲内かを調べる。フォーマットチェックは形式・桁数・文字種が決まりどおりかを調べる。 |
| **組合せチェック** | **照合チェック** | 組合せチェックは複数項目の組合せに矛盾がないかを調べる。照合チェックは入力値がマスタファイルに登録されているかを調べる。 |
| **区分コード（分類コード）** | **桁別コード** | 区分コードは分類ごとに番号の範囲を割り当てる。桁別コードは各桁の位置に分類などの意味を持たせる。 |
| **順番コード** | **表意コード** | 順番コードは通し番号で値から対象を連想できない。表意コードは略号などで値を見れば対象を連想できる。 |
| **パンくずリスト** | **サイトマップ** | パンくずリストはトップから現在のページまでの経路を示す。サイトマップはサイト全体のページ構成を一覧にしたページ。 |
| **レスポンシブ Web デザイン** | **メディアクエリ** | レスポンシブ Web デザインは1つの HTML で画面幅に応じてレイアウトを変える手法。メディアクエリはそれを実現する CSS の機能。 |
| **カルーセル** | **アコーディオン** | カルーセルは複数のコンテンツを横にスライドして切り替える。アコーディオンは見出しをクリックして内容を開閉する。 |

## 一問一答（★★★）

説明を読んで用語を答えてください。クリックすると答えが開きます。

<details><summary>Q1. 特定の利用者が特定の利用状況で目標を達成する際の、有効さ・効率・満足度の度合い（ISO 9241-11）</summary>

**ユーザビリティ**（usability）
</details>

<details><summary>Q2. 高齢者や障害のある人を含め、できるだけ多くの人が製品・サービス・情報を利用できること</summary>

**アクセシビリティ**（accessibility）
</details>

<details><summary>Q3. 複数の選択肢から1つだけを選ぶための GUI 部品</summary>

**ラジオボタン**（radio button）
</details>

<details><summary>Q4. 複数の項目を選択したり、1つの項目の ON/OFF を指定したりする GUI 部品</summary>

**チェックボックス**（check box）
</details>

<details><summary>Q5. 入力データが決められた形式・桁数・文字種に合っているかを調べる入力チェック</summary>

**フォーマットチェック**（format check）
</details>

<details><summary>Q6. 入力値があらかじめ決めた上限・下限の範囲内にあるかを調べる入力チェック（範囲チェック）</summary>

**リミットチェック**（limit check）
</details>

<details><summary>Q7. コードに検査用の文字（数字）を付け、入力時に計算し直して誤りを検出する方法（チェックディジット）</summary>

**チェックキャラクター**（check character）
</details>

<details><summary>Q8. モノの形や性質が、それをどう扱えるかを人に示唆すること（取っ手の形が「引ける」と感じさせるなど）</summary>

**アフォーダンス**（affordance）
</details>

<details><summary>Q9. 1つの HTML を、画面の幅に応じて CSS でレイアウトを切り替え、多様な端末に対応させる手法</summary>

**レスポンシブ Web デザイン**（responsive web design）
</details>

<details><summary>Q10. 利用者の要求を理解し、設計と評価を繰り返してユーザビリティを高める人間中心設計（HCD）のプロセスを定めた規格</summary>

**JIS Z 8530（ISO 9241-210）**
</details>

<details><summary>Q11. 年齢や障害の有無などにかかわらず、最初から多くの人が使えるように設計するための7つの原則（R.メイスら）</summary>

**ユニバーサルデザインの 7 原則**
</details>

<details><summary>Q12. 専門家が経験則（ニールセンの10原則など）に照らして、UI の問題点を洗い出す評価手法</summary>

**ヒューリスティック評価**（heuristic evaluation）
</details>

<details><summary>Q13. 専門家が初めて使う利用者になったつもりで操作手順を1ステップずつたどり、迷う箇所がないかを検討する評価手法</summary>

**認知的ウォークスルー**（cognitive walkthrough）
</details>

<details><summary>Q14. 利用者に考えていることを声に出しながら操作してもらい、つまずいた理由を把握する評価手法</summary>

**思考発話法**（think-aloud protocol）
</details>

<details><summary>Q15. 操作が終わった後で、録画を見ながら利用者に操作中の考えをインタビューする評価手法</summary>

**回顧法**（retrospective method）
</details>
